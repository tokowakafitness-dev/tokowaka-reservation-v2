## 3. 確認画面で止めない（§1 の設計）

### 3-1 名前の状態（rvNameState を改める）
| 状態 | 条件 | 押せるか | 記録の画面へ |

| empty | 名前が空でセットかメモがある | 押せない（今どおり） | — |
| health | 名前に体のことの言葉（MEMO_HEALTH） | 押せない（今どおり・I55） | — |

```

### 3-3 もしかして（候補を出すだけ・自動では置き換えない）
- 候補の元：固定の表の正式名と別名・exMaster の名前。
- 照合（上から順に・同じ候補は1つ）：①memoKey が完全一致 ②**濁点・半濁点・小さい文字・長音を畳んだ鍵**が一致（ド→ト・パ→ハ・ァ→ア・ー を除く）③畳んだ鍵どうしの**編集距離が1**で、鍵が4字以上（短い名前は外れやすい）。②③の候補が3つ以上なら出さない（迷わせない）。
- 別名に当たったら正式名を出す。
- 1タップで名前を候補に置き換える。**置き換えは種目名を変えたことになる**（§3-5）。

### 3-4 別名で自動に正式名へ置き換える（完全一致だけ）
- reviewFromDraft で、AI の名前（trim のみ）が**別名の表に完全一致**したときだけ正式名に置き換え、`name0` も正式名にする（AI が最初からその名前で返したのと同じ扱い＝「種目名を変えた」印は付かない）。**これは設計50 S-H5 の明示の例外**（改訂1）。例外にしてよい理由は、別名の表には「その種目だけを指す語」だけを置き、広い語は置かない（検査 N10 の禁止リスト）ので、別の種目の数字として入る取り違えが起きないこと。
- それ以外（memoKey・畳んだ鍵・編集距離）は**もしかして止まり**（自動で置き換えない）。
- 別名は正式名・ほかの別名と重ならないこと（検査で固定）。

## 4. 固定の一覧を約80種目に（§2 の設計）

### 4-1 置き場所：1つの表に寄せる
```
var EXERCISE_TABLE = [   // [正式名, 部位の鍵, [別名…]]  ★オーナーが直すのはここだけ（付録 A）
  ['ベンチプレス', 'chest', ['ベンチ']],

- **liff/karte.js の上の方に1つの表**として置く（別のファイルにすると index.html の読み込みと版の印が2つになる）。表の上に「直し方」（1行1種目・別名はかぎ括弧で並べる・正式名は今ある記録と同じ文字にする）を書く。
