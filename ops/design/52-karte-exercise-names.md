## 3. 確認画面で止めない（§1 の設計）

### 3-1 名前の状態（rvNameState を改める）
| 状態 | 条件 | 押せるか | 記録の画面へ |
|---|---|---|---|
| empty | 名前が空でセットかメモがある | 押せない（今どおり） | — |
| health | 名前に体のことの言葉（MEMO_HEALTH） | 押せない（今どおり・I55） | — |
| long | 50字を超える | 押せない（今どおり） | — |
| known | 一覧（固定の表・exMaster）と完全一致 | 押せる | regPart なし（今どおり） |
| **guessed**（新） | 一覧に無い・部位をまだ選んでいない | **押せる** | `regPart = guessPart(名前)`（その他を含む） |
| named | 一覧に無い・部位を選んだ（`partFor === 名前`） | 押せる | `regPart = 選んだ部位`（今どおり） |
- 「一覧に無い種目名があります」の理由（2358行）は出さなくなる。代わりに下の帯の件数に「一覧に無い種目 N（部位は推定）」を出す（押せなくはしない）。
- **推定が other のとき**：止めない。チップは「その他（推定）」と出し、タップで直せる。部位は記録の保存には使わず、登録（任意）と表示の並べ方にだけ使う（§1-4）ので、その他のまま入っても記録の数字は誤らない。登録の欄は記録の画面で今どおり任意（初期値が「その他」）。

### 3-2 部位のチップ（1行）
```
一覧に無い種目です　部位：［脚・尻（推定）▾］  ← タップで7つの部位のチップを開く（44px）・選ぶと named
もしかして：［サイドレイズ］［リアレイズ］        ← 最大2つ・1タップで名前を置き換える（44px）
```
- 7つの部位のチップは今の rvNameBox（3131行）の部位のボタンを使う（開いたときだけ並べる＝画面を長くしない）。
- ダイアログは増やさない。

### 3-3 もしかして（候補を出すだけ・自動では置き換えない）
- 候補の元：固定の表の正式名と別名・exMaster の名前。
- 照合（上から順に・同じ候補は1つ）：①memoKey が完全一致 ②**濁点・半濁点・小さい文字・長音を畳んだ鍵**が一致（ド→ト・パ→ハ・ァ→ア・ー を除く）③畳んだ鍵どうしの**編集距離が1**で、鍵が4字以上（短い名前は外れやすい）。②③の候補が3つ以上なら出さない（迷わせない）。
- 別名に当たったら正式名を出す。
- 1タップで名前を候補に置き換える。**置き換えは種目名を変えたことになる**（§3-5）。

### 3-4 別名で自動に正式名へ置き換える（完全一致だけ）
- reviewFromDraft で、AI の名前（trim のみ）が**別名の表に完全一致**したときだけ正式名に置き換え、`name0` も正式名にする（AI が最初からその名前で返したのと同じ扱い＝「種目名を変えた」印は付かない）。
- それ以外（memoKey・畳んだ鍵・編集距離）は**もしかして止まり**（自動で置き換えない）。
- 別名は正式名・ほかの別名と重ならないこと（検査で固定）。

## 4. 固定の一覧を約80種目に（§2 の設計）

### 4-1 置き場所：1つの表に寄せる
```
var EXERCISE_TABLE = [   // [正式名, 部位の鍵, [別名…]]  ★オーナーが直すのはここだけ（付録 A）
  ['ベンチプレス', 'chest', ['ベンチ']],
  ...
];
EXERCISES     = 表の正式名（今の12種目を全部含む・名前を変えない）
```

- **liff/karte.js の上の方に1つの表**として置く（別のファイルにすると index.html の読み込みと版の印が2つになる）。表の上に「直し方」（1行1種目・別名はかぎ括弧で並べる・正式名は今ある記録と同じ文字にする）を書く。
- **今の12種目の名前は1字も変えない**（記録の名前・前回の値・会員のカルテの種目名が名前で結びついている）。
- PART_RULES（推定）は残す（表に無い名前の推定に使う）。表に入った名前は表の部位が勝つ（例：ナローベンチプレスは腕・スカルクラッシャーは腕）。
- exMaster（共有の一覧）と同じ名前があるときは **exMaster の部位が勝つ**（オーナー・トレーナーが登録した部位を上書きしない＝partKeyOf の順）。一覧の並べ方の重複は今の allNames（3871行）の重複除きで1つになる。
