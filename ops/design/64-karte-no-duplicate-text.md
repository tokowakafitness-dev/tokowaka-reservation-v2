# 64 同じ文を2回書かない（消さない・削らない・1回だけ残す）

> 2026-11-26。オーナー指示「細かい情報が残ることを前提としつつ、同じ情報が重複して記載される状況は改善してほしい」。CEO から CTO へ。

## 目的（1行）
細かい情報は全部残したまま、同じ文が社内メモ・お客様の欄・その日のメモに2回書かれないようにする。

## 重複の発生源（実物で確かめた）

## 直し方
- **3**：`commit()` で社内メモへ足す行を `memoMerge` に通す。いまの社内メモにある行・同じ下書きで前に出た行は足さない（既存の行は変えない（末尾の空白・空行だけは今までどおり詰めてからつなぐ））。同じとみなすのは NFKC・空白の詰め・前後の空白の違いだけ。お客様へは足す文の全部の行が既にあるときだけ足さない（1行でも新しければ文ごと末尾＝見出しの組み立てを崩さない）。次回までには同じ項目を足さない。重ねなかった数は入れた後の1行で言う（黙って落とさない）。上限の判定 `rvMemoOver` も同じ関数で数える。
- **4**：`k_importDay` が書く前に、その日に同じ本文（前後の空白の違いだけ）の生きた社内メモがあるかを読み、あれば社内メモだけ書かず `noteSame:true`。記録・体の注意は今どおり。payload の note は元のまま（同じ番号の再送が 409 にならない）。読めなければ今どおり入れる。同じ条件を INSERT 文にも置く（WHERE NOT EXISTS）＝同時に届いた2つ目や読みの失敗でも2件にしない（関門② 中2。競り負けた側の応答の noteId は書かれていない id になる＝取り込みの画面は id を使わない）。画面はその日に「済（同じ社内メモがその日に既にあったため、メモは重ねていません）」。
- **1・2**：AI の指示文に 7. を足す（同じ事実は1つの欄にだけ。種目中の指導＝その種目の note・flow＝何をどの順で行ったかだけ・coaching＝全体の指導だけ・ほかの欄も重ねない・事実そのものは省かない）。`AI_BUILD` 2026-11-26a。出力の形（スキーマ）は変えない。

## しなかったこと（理由）
- 意味の近さでの判定・行の一部の一致：消し過ぎる（片方にしか無い情報が消える）。
- 種目とセットの重複の判定：同じ重さ×回数を2回は正当にある。2回目は「いまの入力の後ろに足す」をトレーナーが押して選んでいる。
- 既存の社内メモ（過去の行）の書き換え・統合：書いた人の文を変えない。
- お客様へ（member_message）と社内の欄の重なり：業務の規則が決まっていない（下の質問）。

## 業務の規則として決めてほしいこと（COO・CEO へ）
1. お客様へ（【今日の内容】）と社内メモ（今日の流れ・指導）に同じ内容が両方あるのは、重複として片方に寄せるべきか、それぞれの読み手のために両方残すべきか（いまは両方残る・AI の指示文の 7. はお客様の欄に触れていない）。
2. 取り込みで「メモだけの日」に日々の画面の社内メモが既にあり、本文が違うとき、既定で入れるか入れないか（いまは入れる＝2件になる。記録のある日は既定で入れない）。

## 戻し方
画面は `memoMerge` を通さず元の連結に戻す。Worker は `noteSame` の読みを外す。指示文の 7. を外す。どれも表は変えていない。
