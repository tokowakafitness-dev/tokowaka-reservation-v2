# 66 AI のセッションログを社内では重ねず、表示される場所に入れる（MECE）

> 2026-11-26。オーナー指示（原文）：「セッションログを残すにあたり、トレーニングのメニューと重量・回数やそのセットの備考がトレーニングログにあれば、本日の流れに同様の重複する内容を書くべきかは疑問に思う。社内に残す情報はMECEに重複なしが理想で、かつそれぞれの情報が表示されるべき場所にインポートされるべきである。その中で顧客側に伝えるべき内容（褒めやおしいポイントや、今後のやって欲しい宿題）は社内のログと重複してしまっても問題ない。」CEO から CTO へ。設計50（AI の確認画面）・設計64（同じ文を2回書かない）の続き。

## 目的（1行）
社内に残す AI の下書きを欄ごとに重ならないようにし、種目とセットのメモはトレーニングログのその種目・そのセットに入れる（お客様の欄は重なってよい＝触らない）。

## 比べた手段（種目のメモの置き場所）
| 手段 | 変える面積 | 戻せるか | オーナー操作 | 表示・編集・取り込みとの整合 | 採否 |
|---|---|---|---|---|---|
| A. 種目のメモの表を足す（`karte_tr_ex_notes(session_id, ord, note)`） | 大：migration・k_addTraining/k_editTraining/k_training・記録の画面・日別・直す画面・過去分の取り込み・改訂の控え | migration は戻せない | 0（マージで流れる） | 全部に新しい欄を足す必要 | ✕ 今回は過大。業務として「種目のメモ」を独立して見たい要望が出たら別の設計で |
| **B. 1セット目のメモに寄せる（読み取るの経路と同じ規則）** | 小：liff/karte.js の reviewBuild だけ。D1・Worker は変えない | revert で戻る | 0 | 既にある：記録の画面・日別・直す画面・過去分の取り込みがセットのメモを扱える。会員には出ない（I-M3） | ◯ |
| C. 今どおり社内メモに「種目名：」 | 0 | — | 0 | オーナーの「表示されるべき場所」を満たさない | ✕ |

**B を選ぶ。** 規則は読み取るの経路（設計40 G8・設計41）とそろえる：
- 種目のメモ（`nセット目：` で始まらない行）→ その種目の **1セット目のメモ**の末尾へ（「・」でつなぐ）
- `nセット目：…` の行（AI のセットの備考）→ その種目の **n 番目のセット**のメモへ（確認画面で直した後のセットの並びで数える）
- 入らないもの＝セットが無い（数字の無い種目）・n 番目のセットが無い・200字（セットのメモの上限）を超える → 今どおり `種目名：…` で社内メモへ（**黙って捨てない**＝I64）

## summary.flow（今日の流れ）
- 指示文：トレーニングの記録に残る種目・重さ・回数・備考以外のことだけを時系列で（例：ストレッチ・カウンセリング・測定・計画の変更とその理由・順番を変えた理由）。種目名・重さ・回数を並べない。無ければ空。
- 入れる側：AI が守らなかったときの網として、**確認画面に出す前に**（reviewFromDraft）、その下書きの種目名・数字・単位・つなぎの言葉（から・→・を・した 等）を除くと何も残らない行だけを今日の流れから外す。トレーナーが見るものと入るものは同じ（入れるときに黙って落とさない）。名前の別名や言い換えで書かれた行は外さない（保守的）。片方にしか無い事実（「ストレッチ」「順番を変えた理由」）は残る。

## 社内の欄の役割（指示文に入れる・1行ずつ）
| 欄 | 書くこと |
|---|---|
| exercises / sets | 種目・重さ・回数（トレーニングの記録） |
| exercises.note | その種目にだけ結びつく指導・フォーム・左右差 |
| sets.note | そのセットだけの出来事（補助・崩れ・やり切れなかった等） |
| summary.flow | 記録に残らないことだけ（上） |
| condition | 今日の体の調子で caution に当たらないもの（疲れ・動きの硬さ等） |
| caution | 痛み・違和感・怪我・診断・服薬・発熱だけ（今どおり・注意することへ） |
| coaching | 種目に結びつかない全体の指導・考え方 |
| hearing | お客様から聞いた生活・食事・睡眠の習慣・仕事・目標だけ |

| member_message / member_todo | **触らない**。お客様の画面に出る欄は社内の欄と重なってよい（7. に明記） |

## 判定できないとき
- 入れられない種目のメモは社内メモへ（今どおりの行き先）＝捨てない
- 今日の流れの網は「除くと何も残らない」ときだけ外す＝迷ったら残す（重なっても事実は失わない側）

## 画面で変わる所
- AI の下書きを記録の画面に入れた後：種目のメモ・セットの備考がそのセットの ✎ の欄に入って出る（社内メモの欄には「種目名：」の行が入らなくなる）。保存すると日別の記録で `1セット目：…` として出る
- ✓ を付けないセットのメモは送られない（今どおり。保存の前に「記録されない入力が n セット」の確認が出る＝セットのメモも数える）

## 業務の規則として決めてほしいこと（COO・CEO へ）
1. 種目のメモを「1セット目のメモ」に置くことで足りるか、種目ごとの欄（手段 A）が要るか（1セット目を消すとメモも消える・日別では「1セット目：」と出る）
2. 数字の無い種目（実施のみ）の種目のメモは社内メモに残る（置く先のセットが無い）。これでよいか
3. ✓ を付けなかった1セット目にメモがあると送られない（保存前の確認で数える）。セットのメモを✓と無関係に残すべきか
