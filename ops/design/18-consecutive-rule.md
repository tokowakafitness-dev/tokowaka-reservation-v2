# 18 同じトレーナーの連続を3時間で区切る（顧客が取る予約だけ）（設計）

> 起草：2026-10-13／**第7版・関門①通過**（7往復・指摘23件）
> 置き換えるもの：`03-auto-break.md`（10/02・「直後に休憩を書く」方式）。**連続の「前」を塞げない**ため採らない（§5）

---

## 0. ルール（オーナー確定 2026-10-13）

```
1. すでに3時間続いている（同じトレーナーの）予約の、すぐ前とすぐ後は15分あける
2. ただし、予約と予約のすき間を埋める予約は、つながっても5時間までは認める（1より優先）
3. どんな場合も、連続5時間を超える予約は取れない
```

| 前提 | 決定 |
|---|---|
| 「連続」とは | 同じトレーナーの**セッション**どうしの間が**15分未満**。ちょうど15分あいたら別の連続 |
| 誰の連続か | **トレーナーごと**。交代しながら全体で5時間を超えるのは問題にしない |
| 体験 | **連続の時間に数えない**（体験90分は無いものとして数える） |
| 休憩・ブロック | セッションではない＝連続を区切る（既存の `_lbIsSessionTitle` と同じ） |
| 効かせる予約 | **顧客が自分で取る予約だけ**。トレーナー代行・管理画面の枠作成・固定枠の自動予約・ホットペッパーには効かせない |
| ホットペッパー | 後回し（頻度を数えてから判断） |

## 1. 判定（1つの純粋関数で決める）

その枠 `[s, e)` を入れたとき、同じトレーナーの（体験を除く）セッションと「間が15分未満」でつながるものを集めて、つながった連続の長さ `L` を出す。
`L` は**幅**（最初の開始〜最後の終了。15分未満の隙間も含む）。実働の合計ではない（既存の監査 `spanMinutes` と同じ）。

| 枠の位置 | 可否 |
|---|---|
| どこにもつながらない | ○ |
| **片側だけ**につながる（端を伸ばす） | `L ≤ 180分` なら ○ |
| **両側**につながる（すき間埋め） | `L ≤ 300分` なら ○ |

- ルール1は「片側だけ・L≦180」、ルール2は「両側・L≦300」、ルール3は両方の上限が300以下であることで満たされる。
- 片側で 180分を超えるのは、**すでに3時間ある連続を伸ばす**場合（オーナー確定）と、**2.5時間の連続に60分足して3.5時間になる**場合。
  ★後者は**未確認**。ルールの字面（「すでに3時間続いている」）では ○、趣旨（3時間で区切る）では ×。
  推奨は × （判定が「片側なら L≦180」の1行で済む）。15分刻みで取れる枠があるので起こりうる。**オーナーに確認する**
- オーナーが示した例はすべて下表で一致する

| 例（10:00〜13:00 が埋まっている） | L | 位置 | 判定 |
|---|---|---|---|
| 13:00〜14:00 | 240 | 片側 | × |
| 13:15〜14:15 | 60 | なし | ○ |
| 9:00〜10:00 | 240 | 片側 | × |
| 8:45〜9:45 | 60 | なし | ○（7:45〜8:45 も ○） |
| 9:00〜11:00 と 12:00〜13:00 の間の 11:00〜12:00 | 240 | 両側 | ○ |
| 9:00〜12:00 と 13:00〜14:00 の間の 12:00〜13:00 | 300 | 両側 | ○（ルール2優先・オーナー確定） |
| 9:00〜12:00 と 13:00〜15:00 の間の 12:00〜13:00 | 360 | 両側 | × |

## 3. 設計

### 3-1. 判定は1つの純粋関数（`BookingRules.js`）

```
_lbConsecVerdict(sessions, slotStart, slotEnd, opt)
  sessions … そのトレーナーの（体験を除く）セッション [{start,end}]（ms）
  返り値   … { ok, lengthMin, existingMin, side: 'none'|'one'|'both', invalid }
     existingMin … none: 0 ／ one: 足す前につながる片側の連続の幅 ／ both: null（使わない）
     invalid     … 入力が読めない（開始≧終了・数でない）。このとき ok:false（答えない側）
  規則     … §1 の表。gap=15・両側上限300
  opt.oneSideMode … 片側（端を伸ばす）の判定。★数値1つでは切り替えられない（上限を300にすると 10-13 に 13-14 を足す例まで通る）
     'result_max_180'（既定・推奨）       … 足したあとの L ≦ 180
     'existing_run_under_180'（字面どおり） … 足す前の既存の連続が 180 未満、かつ L ≦ 300

```
- `BookingRules.js` に置く（module.exports があり、Node の検査から require できる）。GAS ではグローバル。
- `_consecRuns` / `_consecWithSlot`（EdgeAudit.js）は**監査用のまま残し、使わない**。判定の正本を1つにする（2か所あると境界 `>`/`>=` がずれる。03 §5 で既に指摘されている）。

### 3-2. 体験の見分け方（★第2版で変更）
- B1 の予定のタイトルは、どの経路でも `[RESERVED] <種別>_<担当の姓>_<顧客名>様`（LINE・HP体験・管理画面・ホットペッパー。請求の集計も同じ形を読む）。
  ★ホットペッパーの予定を作るのは**別のリポジトリ**（`30_projects/personal-training/hpb-mail-to-calendar/gas/sync.js:13, 309`）。このリポジトリの検査に**実際のタイトルの標本**（`[RESERVED] HPB体験_鈴木_山田様` 等）を置いて解析を固定する。`_lbClassifyBooking` は種別の完全一致 `体験` しか持たない（BookingRules.js:20-21）ので、今回は「種別に `体験` を含む」で判定し、その差を検査に書く
- トレーナー T のセッション S が体験 ⇔ **S と時刻が重なる B1 の予定のうち、`種別` に「体験」を含み、`担当の姓` が T の姓と一致するものがある**。
  ★時刻の重なりだけで決めない（第1版の穴：B1 で A の体験、1F で B の通常が同時刻だと、B の通常まで体験として外していた）
- `[消化]` の予定は見ない（席が空いた取消の記録）。
- タイトルが形に合わない B1 予定は「体験ではない」とみなす＝**数える側に倒す**（枠が減る・弾かれる側。顧客に4時間連続を取らせる側には倒れない）。
- ★姓→トレーナーの表は、枠を作る／確定するたびに `CALENDAR_IDS.TRAINERS` から作る。**同じ姓が2人いたらその姓は曖昧**＝体験として外さない（数える側）。いまの3名は姓が異なる（コード.js:9-12）が、将来の追加で黙って壊れないようにする
- 既存の `_lbClassifyBooking`（BookingRules.js:21-45・姓→trainerId）と同じ解析にそろえる（使えるならそれを使う。`HPB体験` の扱いの差は検査で固定）
- 体験は sessions から取り除く（＝連続を区切る）。

### 3-3. 段階ごとの枠（★第2版で変更：off は今と完全に同じ）

`LB_CONSEC_RULE`（Script Properties）

| 段階 | 枠の作り方 | 印 | 顧客に見える枠 | 確定時 |
|---|---|---|---|---|
| 未設定／`off` | **今のまま** | 付けない | 今のまま | 判定しない |
| `dry` | 今のまま | **付けない**（画面には何も足さない） | 今のまま | 判定して記録だけ（`would_reject`） |
| `on` | 今の枠 ＋ **追加の候補**（下） | 全部に `consecOk: true/false` | **`consecOk === true` だけ**（印が無い枠は出さない） | 判定して弾く |

**追加の候補（on のときだけ）**：吸着は空きブロックの**先頭**から刻むので、判定で落とすだけでは 13:15 も 7:45 も生まれない（第1版の「2通りの空きブロック」では 7:45 が出なかった）。そこで、3時間以上の連続 R ごとに開始時刻を直接足す：
- 後ろ：`R.end + 15分`
- 前：`R.start − 15分 − 60分×k`（k=1,2,…）。**その空きブロックの先頭を割らない範囲で**（例：10:00開始・ブロック7:00〜 → 8:45, 7:45。7:00〜7:45 は調整の余白＝オーナーの意図）
- 足した候補も、今の枠と**同じ条件**を全部通す：その時刻を含む空きブロックに60分収まる／締め切り／オーナーの曜日×時間帯／`trialOk` の式
- 同じトレーナー・同じ開始は1つ。今の枠は1つも消さない（トレーナーには全部見える）

### 3-4. 印を運ぶ経路（★第4版：モードは写し全体に明記する）

★枠の項目だけからモードを決めない（第3版の穴：変換で印が全部落ちると、on の写しを off と取り違えて全枠を出す）。
写し全体に `consec: { mode: 'off'|'dry'|'on', version: 1 }` を書く。枠の印 `consecOk`（真偽値）は **on のときだけ**全部の枠に付ける。

| 段 | 変えること |
|---|---|
| `buildAvailableSlots` | on のとき追加の候補と `consecOk` |
| `buildAndCacheSlots` のキャッシュ（コード.js:202-223・**配列のまま**） | 枠に `consecOk` を足す（on のときだけ）。★キャッシュ全体は配列のまま（包むと `_lbDropClosedSlots` 等の `.filter` が壊れ、配列に項目を足しても JSON に残らない）。モードはキャッシュに持たせない |
| 内部用 `_lbTrainerSlotsAll(trainerId, excludeStartISO)`（新） | 今の `getTrainerSlots` の中身（絞らない全部の枠）。**写しへ送る処理・内部の呼び出しはこれだけを使う** |
| `getTrainerSlots(body, lineUserId)`（GAS・顧客とトレーナーの入口） | `_lbTrainerSlotsAll` を呼び、顧客なら絞る。モードは Script Properties を直接読む |
| 公開シート（9列・HP体験用） | **変えない**（HP体験は対象外） |
| `_edgeSlotRows`（PushToEdge.js:483-519）→ slots_cache の payload | ★作りたての枠が無いときの落ち先（PushToEdge.js:492 の `getTrainerSlots({trainerId})`）を **`_lbTrainerSlotsAll` に替える**（顧客用に絞った枠を写しに入れない＝トレーナーから枠が消えない）。枠に `consecOk` を運ぶ。payload の `consec` は**枠そのものから決める**（下） |

★**payload のモードは「作った枠」と「いまのスイッチ」を組み合わせて決める**（第5版の穴：作ったあと・送る前にスイッチを変えると枠とモードが食い違う／第6版の穴：印が変換で全部落ちると off として送り、禁止の枠を顧客に出す）

| 変換**前**の枠（送る全トレーナー分を通して） | いまのスイッチ | 処理 |
|---|---|---|
| 全部に真偽値の `consecOk` | どれでも | `mode:'on'`。★**変換後も全部に真偽値が残っていなければ送信ごと中止** |
| 1つも `consecOk` を持たない | off / dry | `mode:'off'`（従来の形） |
| 1つも `consecOk` を持たない | **on** | **送らない**（切り替え直後か、取りこぼしか、区別できない＝答えない側）。Worker は前の写しのまま→古くなれば GAS へ落ちる（GAS は自分で正しく絞る）。次の作り直し（≦10分）で印つきの枠になる |
| 混ざっている（トレーナー1人分だけ落ちた場合も含む） | どれでも | **送信ごと中止** |
| 0件 | どれでも | いまのスイッチの値 |

- 切り替えの競合も安全：on で作って off に変えた → 枠は全部印つき＝`mode:'on'`（枠と一致）／off で作って on に変えた → 送らない。
- 見張り `CONSEC_DISPLAY_MISS`（スイッチ on なのに写しが on でない状態が20分続く）は**防御ではなく追加の見張り**として残す。

**Worker が顧客に返すとき**
| payload の `consec` | 返すもの |
|---|---|
| `mode:'on', version:1` | `consecOk === true` の枠だけ。**`consecOk` が真偽値でない枠が1つでもあれば `_fallback`**（GAS へ。GAS は自分のモードで絞る） |
| `mode:'off'` / `'dry'` | 今のまま |
| 無い（反映前に作られた古い写し） | 今のまま（★10分以内に作り直される。点検 `CONSEC_DISPLAY_MISS` が「on なのに写しに consec が無い」を high で出す） |
| 知らない mode / version | `_fallback` |
- 空の枠（0件）でも payload の mode で判定できる。
- トレーナー（`who.role` が customer 以外）には今のまま全部返す。

**見張り**
- `CONSEC_DISPLAY_MISS`：日次点検。スイッチが on なのに Worker の写しの payload が `mode:'on'` でない（作り直しの周期を2回以上越えて）→ high
- `CONSEC`：確定時に連続ルールで弾いた件数（表示のあとに別の予約が入った競合も含む）
- `CONSEC_UNKNOWN`：確定時にカレンダーが読めず弾いた件数

### 3-5. 顧客にだけ絞る
| 入口 | 絞り方 |
|---|---|
| Worker `compatTrainerSlots` | `who.role === 'customer'` なら §3-4 の規則で絞る |
| GAS `getTrainerSlots` | **3つの入口すべてで、検証済みの lineUserId を別引数で渡す**（body の値は使わない）。`getTrainerByLine` でトレーナーでなければ、on のとき `consecOk === true` だけ。トレーナー表が読めないときも顧客側に倒す |
| ★on に切り替えた直後の古いキャッシュ | on なのに `consecOk` が真偽値でない枠を含むキャッシュは**キャッシュ外れとして扱い、その場で作り直す**（既存のキャッシュ外れの経路＝`buildAndCacheSlots`）。作り直しても印が無ければ**枠を返さず失敗で答える**（全部を見せない・0件とも言わない）。これで切り替え直後（キャッシュの寿命は最大11分）に枠が消える／全部出る、のどちらも起きない |

### 3-6. 確定時の判定（顧客の操作だけ）
- `custInfo.consecRule = true` を立てた経路だけ、`_lbReserveCoreImpl` で `_lbCheckTrainerAvailable` の直後・カレンダー作成の**前**に判定。
- 立てる経路：`makeReservationLine`・`makeRecurringReservationLine`・`makeBatchReservationLine`（本人）・`makeTransferReservationLine`・**`changeReservationLine` で操作者の LINE ID が予約の line_user_id と一致するとき**（＝自分の予約を自分で変える。トレーナーが自分の予約を顧客画面で変える場合も含む＝その人は顧客として振る舞っている）
- 立てない経路：代行・他人の予約をトレーナーが変える・固定枠の自動予約・管理画面の枠・ブロック・HP体験・ホットペッパー
- 読む範囲：その日（JST 0:00〜24:00）のトレーナーcal と B1（+2回の読み取り）。営業は 7〜24時で日をまたがない
- ★**読めなかったら弾く**（MODEL §0）：`{ok:false}` なら `SLOT_TAKEN` を返し、記録は `CONSEC_UNKNOWN`。dry では弾かず `UNKNOWN` として数える
- 弾く答え：`SLOT_TAKEN`（既存のコードと文言）。記録の理由は `CONSEC`

- ①は本番で使われていない。今回は入れない。★`SLOTS_FROM_CALENDAR` を有効にする前に①へ入れることを検査で止める（wrangler.toml で有効なのに calslots に判定が無ければ落ちる）
- ホットペッパーは後回し

### 3-10. 切り替えの手順（オーナーの操作は Script Properties の1か所）
1. 反映（未設定＝off。何も変わらない）
2. `LB_CONSEC_RULE=dry` … 数日、確定時の `would_reject` を数える（影響の実測）
3. `LB_CONSEC_RULE=on` … 次の warmupCache（最大10分）で枠と写しが作り直される。その間に GAS へ来た顧客は 3-5 の作り直しで正しい枠を見る。Worker は古い写し（consec 無し）の間は今のまま、作り直された写しから絞る
