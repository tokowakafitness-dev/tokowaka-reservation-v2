# 65 カルテのトレーナー画面から説明文を削る（直感でわかる画面に）

> 2026-11-26。オーナー指示（実機スクショ2枚・本番 2026-11-26f）：「どのような挙動になるのかの説明は不要。情報は必要最小限に、直感でわかる状態にする。もし注意書や説明が必要なら、項目ごとに?マークをつけ、タップしたら説明が表示される状態でもいい」「一枚目も説明不要」。CEO から CTO へ。

## 目的（1行）
トレーナー画面の挙動の説明文・案内の帯を消し、毎回は要らない注意は「?」に畳み、判断や行動が要るものだけを短く残す。

## 比べた手段
| 手段 | オーナー操作 | 戻せるか | 変える面積 | 採否 |
|---|---|---|---|---|
| A. 文言を全部消す | 0 | git で戻せる | 小 | ✕ 同意（rec_ai）・健康（I48/I55）の表示まで消える |
| B. 消す／?に畳む／残すの3つに分け、?は共通の部品1つ | 0 | git で戻せる | 中（liff/karte.js のみ・Worker は触らない） | ◯ |
| C. 設定で説明の表示を切り替える | 設定の操作が要る | 戻せる | 大（状態が増える） | ✕ 状態を増やすだけ |

## 共通の部品「?」（`qhelp`）
- 項目の横に小さな「?」ボタン（見た目 22px の丸・**タップ領域 44×44px**）。`aria-expanded`・`aria-label="説明"`。
- タップで直下に説明を開く／もう一度で閉じる。**説明は開いたときだけ DOM に作る**（閉じているときは画面にも読み上げにも出ない）。
- ダイアログは使わない（確認を増やさない）。片手で押せるよう行の右端に置く。
- 部品は `helpRow(node, helpText, cls)`＝[項目][?]の行＋開いた説明。`cls` は外側の箱（`k-qwrap`）に付け、開いた説明は `k-qbody`（検査は `.<cls> .k-qbody` で見る）。

## 取り込んだ直後の通知（`k-toast`）
- 記録の画面の上の青い帯（「メモから n種目・nセットを入れました。✓を付けて…（✓の無いセットは保存されません）。文章 n行は…重ねて入れませんでした…AIの下書きを…」）を、**「n種目を入れました」だけの短い通知**にする。3.5秒で消える（タップでも消える）。
- 種目が0で文章だけ入れたときは「入れました」。
- 日付が食い違うとき（メモの日付≠記録の日付）は判断が要るので、今どおり `k-impdate` の1行で残す。空の下書きの日付をメモの日付にしたときは見出しの日付が変わるだけなので、通知に日付を添える（「9/18 に 7種目を入れました」）。
