会員がキャンセルするときに「理由（選択肢）＋ひとこと（任意）」を受け取り、その枠のトレーナーと契約上の担当に届ける。

## 1. 倒れる向き

```
理由・ひとことは「おまけ」。判定できない・保存できない・長すぎる・知らない鍵 → **理由を捨ててキャンセルは成立させる。**
理由のせいでキャンセルが失敗することは一度もあってはならない。
理由を捨てたときは、会員に「お伝えします」と言わない（noteSaved が true のときだけ言う）。
```
- 長すぎるひとことは**切り詰めない**（途中で切ると意味が変わる）。丸ごと捨てて、会員の画面に「ひとことはお送りできませんでした」と出す。
- 「お伝えしました」とは書かない。トレーナーへの通知が送り直しの列に積まれている可能性があるので「お伝えします」と書く。

## 2. 守る不変条件

1. **台帳の備考（9列目）は予約の鍵。理由・ひとことを一切入れない。** 備考を鍵として使っている場所は次の4つ（実装の前に grep で数え直す）：
   - `cancelReservationLine`：`String(r[8]) === reservationId` の**完全一致**で行を探す（取消の前の行）
   - `undoSameDayCancel`：`note.indexOf(resId + LB_SDC_TAG + '→無料取消') === 0` 等の**前方一致・完全一致**
   - `_lbNqFindResv`（送り直し・I17）：`split('|')[0]`
   - gas/Nudge.js の振替の判定：`_lbNudgeResId` で `split('|')[0]`
   - ほか `_edgeReservations`（D1 の写しの予約ID）も `split('|')[0]`
2. **キャンセルの判定（無料／当日消化／オーナーの無料）は1文字も変えない。** `_lbIsFreeCancelWindow`（前日17時）・`_ownerFreeReq`・振替権の付与（`_lbGrantTransferCredit`）はそのまま。
3. **理由の欄はキャンセルの成否に影響しない**（§1）。キャンセルが成功した応答の形は今と同じで、`noteSaved`（真偽値）と `noteDropped`（理由の文字列）を**足すだけ**。
4. **健康情報の扱い（I48・I55 の精神）**：ひとことは健康情報を書く場所ではない。入力欄の真下に注意書きを置く。**cancel_notes からカルテ（D1 の karte_*）へは何も写さない**（自動でも手動のボタンでも作らない）。選択肢「体調・コンディション」は区分だけで、部位・症状を選ばせない。
5. **ひとことは機密に準じて扱う**：ログ（Logger・console）・作業依頼の結果・公開リポジトリに**本文を出さない**。件数と鍵だけ。作業依頼の結果は必ず `_ejScrub` を通す（I28）。
6. **送り直し（I17・I18）を変えない**。トレーナー宛の通知は今と同じ用途 `cancel_trainer`・同じ ctx（resId・customerId・startMs）で積む＝送り直しの判定（取消の状態か・開始前か）がそのまま効く。
7. **LINE の送信中にロックを延ばさない**（I19）。理由のための通信（外部への問い合わせ）をロックの中に足さない。
8. 公開リポジトリ・ログに氏名・フル ID を出さない（I38）。

## 3. 作るもの

### 3-1 会員の確認の画面（liff/index.html）

- 「あなたの予約」の「キャンセル」を押したら、`window.confirm` の代わりに**新しい画面 `s-cxl`** を出す（SCREENS に足す＝戻るの決まりに乗せる）。
- 画面の中身（上から）：
  1. 見出し「ご予約のキャンセル」と、日時・担当（文字として入れる＝textContent）
  2. **今の確認の文をそのまま**出す（`confirm_cancel_free`／`confirm_cancel_transfer`／`confirm_cancel_penalty` の3種。鍵も文も変えない）
  3. 「よろしければ理由をお聞かせください（任意）」と選択肢4つ（**1つだけ選べる・選び直せる・もう一度押すと外れる**）
     | 鍵 | ja | en | zh | zh-Hant |
     |---|---|---|---|---|
     | `work` | 仕事・急な予定 | Work / sudden plans | 工作・临时安排 | 工作・臨時安排 |
     | `family` | 家庭の事情 | Family reasons | 家庭原因 | 家庭原因 |
     | `condition` | 体調・コンディション | Health / condition | 身体状况 | 身體狀況 |
     | `other` | その他 | Other | 其他 | 其他 |
     （訳は下書き。4言語の鍵は他の画面と同じ辞書に足す）
  4. ひとこと（textarea・任意・**100字**・残りの字数を出す）。placeholder「担当トレーナーへのひとこと（任意）」
  5. 注意書き（入力欄の真下・I55 と同じ置き方）：「体調の詳しい内容（痛み・診断・お薬など）は、こちらではなく担当トレーナーへ直接お伝えください。」（4言語）
  6. ボタン：「キャンセルする」（btn-danger・44px 以上）／「戻る」（`data-back`）
- **必須にしない**：何も選ばず何も書かなくても「キャンセルする」は押せる。
- **字数の数え方**：コードポイントで数える（`Array.from(s).length`）。絵文字1つ＝1字。101字以上は送信ボタンを押せなくし、欄の下に「100字までです」。前後の空白を落とし、空になれば送らない。改行は送ってよい（最大3行。それ以上は1つの空白にまとめる）。
- **言語切替で入力が消えない**：選んだ鍵とひとことは `state.cxlDraft = { resId, key, note }` に持ち、`state._repaint` で描き直すときに戻す（`openConfirm(slot, true)` と同じ「keep」の作り）。別の予約の画面を開いたら `cxlDraft` を捨てる（resId が違えば戻さない）。
- **戻るの決まり**：画面の「戻る」は `data-back`。横スワイプ・端末の戻るは `rsvBack` が見えている `data-back` を押す。入力があれば既存の `_formTouched` が「入力中の内容は消えます。前の画面に戻りますか？」を出す（今の決まりのまま）。送信中は戻らない（`_busyEl`）。
- **17時をまたいだとき**：画面を開いたまま前日17時を過ぎると、出している文（無料）と実際の判定（当日消化）が食い違う。送信ボタンを押した瞬間に `r.startISO` と端末の時刻で `_lbIsFreeCancelWindow` と同じ式を計算し直し、**判定が変わっていたら送らずに文を出し直す**（「17時を過ぎたため、1回分の消化となります」）。最終の判定はいつもサーバー（今どおり）。
- 送信の後：
  - 成功・`noteSaved === true` → 「キャンセルしました。ひとことは担当トレーナーにお伝えします。」
  - 成功・ひとことが空 → 今どおり（文を足さない）
  - 成功・`noteDropped` あり → 「キャンセルしました。ひとことはお送りできませんでした。」
  - その後は今どおり（当日消化で振替でなければ振替の案内 `confirm_transfer_offer`→`startTransfer`、それ以外は `loadMyReservations`）
  - 失敗・すでに取消済み（`_alreadyGone`）・通信の失敗 → 今どおり。**下書きは残す**（もう一度押せる）。`cancelReservation` は `_NO_RETRY` のまま（自動で送り直さない）

### 3-2 送り方（GAS への渡し方）

**推奨：今の JSONP の GET のまま、引数を2つ足す**（`cxlReason`＝鍵／`cxlNote`＝ひとこと）。

| 案 | 中身 | よい点 | 悪い点 |
|---|---|---|---|
| **A（推奨）JSONP の GET に足す** | `line_cancelReservation&reservationId=…&cxlReason=work&cxlNote=…` | 経路が1本のまま。キャンセルとひとことが同じ1回の要求＝片方だけ届く形が無い。GAS の入口・認可（`verifyLineIdToken`）をそのまま通る | ひとことが URL に載る（下の「URL に載ること」） |
| B GAS の doPost へ fetch | 本文で送る | URL に載らない | `doPost` は旧経路で、GitHub Pages からの fetch は「CORS で不可」とコードに書かれている（handleLineGet の注記）。**実際に通るか未確認**。確かめるには GAS の反映が要る（上限200本）。応答が読めない形だと成否が分からない |
| C ひとことだけ Worker へ POST・D1 に置く | キャンセルは今の経路、ひとことは Worker | URL に載らない | GAS が通知を作るときに Worker へ問い合わせる＝**キャンセルのロックの中に外部通信が入る**（I19 の精神に反する・キャンセルが遅くなる・新しい失敗の形）。2つの要求の片方だけ通る形が生まれる |

**URL に載ること（オーナーへの説明に使う文）**：
- ひとことは、ブラウザから Google（GAS）へ送る**住所の一部**に入る。いま既にログインの合言葉（idToken）が同じ形で載っていて、記録上は Google の実行の記録に残りうると決定0033の補遺で整理している。
- ひとことの行き先は、どのみち **Google のスプレッドシート（cancel_notes）・トレーナーの LINE・届かなかったときのオーナーのメール**である。URL に載ることで新しく増える見え先は、Google 側の要求の記録だけ（同じ Google のアカウントの中）。外部の第三者に新しく渡るわけではない。
- だから案A を推奨する。ただし次を守る：長さを100字に固定（両側で検査）・GAS 側でログに本文を出さない（今の `handleLineGet` は action 名しか出していない＝変えない）・`edgeAfterWrite` に本文を渡さない（今も params の customerId しか見ない＝変えない）。

**URL の長さ**：idToken（JWT・約1,000〜1,300文字）＋予約ID＋ひとことの最悪（100字すべて4バイトの絵文字＝`encodeURIComponent` で1字12文字＝1,200文字）で、全体は約2,700文字。GAS の Web アプリが受けられる URL の長さは**未確認**（§5）。検査で「最悪の URL の長さ」を計算して上限（仮に 6,000 文字）以下を確かめ、反映後に `--live` で最悪の長さを1回通す。

### 3-3 GAS 側（gas/LineBooking.js）

- 入口：`case 'line_cancelReservation': return cancelReservationLine(lineUserId, params.reservationId, { cxl: { reason: params.cxlReason, note: params.cxlNote } });`
  - `line_ownerFreeCancel` には足さない（オーナーの操作に会員の理由は無い）
- 理由の整え方（新しい関数 `_lbCxlNormalize(raw)` → `{ key, note, dropped }`）：
  - key：`work|family|condition|other` のどれかでなければ `''`（**400 にしない**＝§1。捨てた数を記録）
  - note：文字列でなければ `''`。制御文字を落とし、改行を最大3つにまとめ、前後の空白を落とす。コードポイントで100字を超えたら `''`・`dropped='too_long'`
  - 会員本人の操作のときだけ受け取る。トレーナー・オーナーが同じ入口で送ってきた `cxl` は捨てる（第1段。第2段で別の引数にする）
- 保存（**台帳の更新と振替権の付与が終わった直後・通知の前**）：`cancel_notes` に1行足す（§3-4）。書く値はすべて `sanitizeCell` を通す（`=`・`+`・`-`・`@` で始まる文を数式にしない）。**書けなかったら**：例外を握りつぶしてキャンセルは成功で返す・`noteSaved=false`・`noteDropped='save_failed'`・`booking_metrics` に `CXL_NOTE_SAVE_FAIL` を1行（本文は書かない）
- 台帳の備考（9列目）に書く値は**今と1文字も同じ**（`resId|無料取消`／`resId|当日消化取消`／`resId|無料取消（オーナー権限 …）`）
- 応答：今の `{ success, penalty, ownerFree, customerId }` に `noteSaved`・`noteDropped` を足す
- 版の印：`LB_EDGE_BUILD` 等、LineBooking.js の版の印を上げる（MODEL §8）

- **保存期間（推奨）**：`note`（ひとこと）は**1年**で空にする。`reason_key` 以下の行そのものは**2年**残す（キャンセルの傾向・設計37の計測に使う。氏名は持たない）。オーナーに決めてもらう（§4-3）。
- **消す仕組み（トリガーを増やさない）**：`cancel_notes` に1行書くたびに、**先頭から最大20行**の `cancelled_at` を読み、1年を過ぎていて `note` が残っている行の `note` を空にして `note_purged_at` を書く（行は消さない＝行の番号がずれない）。キャンセルは毎週ある見込みなので、遅れても「1年＋次のキャンセルまで」。
  - 見張り：日次点検（dailyHealthCheck）は**先頭の1行だけ**読み、「ひとことが残っている最も古い行の日付」が400日を超えたら悪化として出す（点検を重くしない。点検は以前 557 秒まで膨らんだ＝MODEL・feedback）。

### 3-5 通知（gas/LineBooking.js の `cancelReservationLine` の後半）

- **その枠のトレーナー宛**（今の `【予約キャンセル】…` の文の末尾に足す。会員の操作で、鍵かひとことがあるときだけ）：
  ```
  【予約キャンセル】{氏名}様
  日時：{日時}
  （無料取消）
  理由：仕事・急な予定
  ひとこと：{ひとこと}
  ```
  - 理由の表示名は日本語の固定表（トレーナー宛は日本語固定のまま）。ひとことは会員が書いたとおり（訳さない）
- **契約上の担当が別の人なら、その人にも同じ文を送る**（オーナー決定）。担当は `_lbCustTrainerId(customerId)`（customer_line_map の担当）。その枠のトレーナーと同じ・担当なし・LINE が無い・読めないときは送らない（**読めないときは送らない側**＝担当を推測しない）。用途は同じ `cancel_trainer`・同じ ctx（送り直しの判定がそのまま効く）。文の頭に「（担当のお客様です）」を1行足し、どちらの立場で受け取ったか分かるようにする
  - ★理由もひとこともないキャンセルでは、担当への追加の1通は**送らない**（今の通知量を増やさない）。オーナーに確認（§4-2）
- **会員宛**（`push_cancelled`＋`push_cancel_*`）の末尾に、`noteSaved === true` のときだけ1行足す：
  | 鍵 | ja | en | zh | zh-Hant |
  |---|---|---|---|---|
  | `push_cancel_note_relayed` | `\nひとことは担当トレーナーにお伝えします。` | `\nWe will pass your message on to your trainer.` | `\n您的留言将转达给负责教练。` | `\n您的留言將轉達給負責教練。` |
  ひとことの本文は会員宛に**写さない**（会員の LINE に残す意味が無い・送り直しの列に本文を増やさない）。
- 通知を送る順番・ロックの中で送ることは今のまま（今の作りに合わせる。直すなら別の設計）。

**送り直しの列（notify_retry）にひとことが残る件**：
- `_lbNqOnFail` は本文（text）ごとシート `notify_retry` に積み、送り直しは積んだ本文をそのまま送る。届かず諦めたものは**オーナーへのメールに本文ごと載る**（`_lbNqMailAlerts`）。
- **推奨：送り直しの本文に含める**（外すとトレーナーが理由を受け取れない。送り直しの目的に反する）。そのかわり、`notify_retry` の**終わった行（sent・alert で通知済み）の本文を30日で空にする**処理を `lbNotifyRetryTick`（warmupCache に相乗り・ロックを持って行を触る既存の作り）の末尾に足す。1回あたり最大50行・使ってよい時間の残りがあるときだけ。
  - ★これは既存の穴も塞ぐ：今の `notify_retry` は氏名入りの本文を**消さずに持ち続けている**（grep で削除の処理が見当たらない・§5 で確かめる）。
- オーナーへのメールにひとことが載るのは許容する（オーナーは全部を見てよい立場）。

- **OUTCOME_CHANGED の freeCancel** は判定そのもの（会員の入口では `_lbIsFreeCancelWindow` の値）。
- **時間予算の判定**は、担当と会員のそれぞれを送る直前に「受付から12秒」「通知開始から4秒」の両方で見る。掃除は受付から12秒を過ぎていたら見送る（次のキャンセルで追いつく）。
- **booking_metrics に書くのは何か起きたときだけ**：CXL_NOTE_HEADER／CXL_NOTE_SAVE_FAIL／CXL_REASON_DROPPED／CXL_NOTE_TOO_LONG／CXL_NOTIFY_SLOW（積んだ・4秒超・受付から12秒超）。毎回の所要時間は Logger の `[perf] cancel notify` に出す（キャンセルのたびに表へ1行足して遅くしない）。`getBookingMetrics` は CXL_ を予約の成否と別に数える（`cxl`）。
- **画面**：完了の文は、当日消化（振替の案内が出る）なら案内と同じ確認の窓の先頭に、それ以外は alert で出す。失敗（BAD_EXPECTATION・通信の失敗・その他）は画面に留まり、下書きを残して押し直せる。`r.freeCancel` が真偽値でなければ当日消化側の文を出し、cxlExpect は空（比べない）。
