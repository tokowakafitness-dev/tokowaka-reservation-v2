## 0. 目的（1行）

録音の文字起こしから、AI に**まず「今日のセッションで実際に何があったか」を推論してまとめさせ**、それをもとに種目・重さ・回数・セットと種目の備考・お客様の状態・次回やることをカルテの形に割り振り、
**不明確なところに「要確認」の印を付けた下書きを1画面で一度に見せ、トレーナーが直して入れる**。AI の出力は今どおり保存しない（I71・I76-6）。

## 5. Worker（routes/karte-ai.js）

### 5-1 切替
```
KARTE_AI_FORMAT   "v1"（既定）／"v2"。厳密一致。それ以外は v1
```
- `[vars]` に足すだけ（D1/KV の結びつけは触らない）。応答の `draft.v` に 1 か 2 を入れる。画面は `draft.v` で分ける（古い画面に v2 が届いたら「画面を開き直してください」・保存しない）。

### 5-2 指示（AI_SYSTEM v2・要点）
1. **最初に、文字起こし全体から「今日のセッションで実際に何があったか」を推論して `summary.flow` に時系列の短い文で書く**（話し言葉の言い直し・聞き違い・予告と実施の区別を、前後の流れから推論してよい）。
2. その要約に沿って、種目・セット（重さ・回数）・セットの備考・種目の備考・お客様の状態・次回やること・お客様へ・次回までに を割り振る。
3. セットごとに `basis`：文字起こしにその数字がそのまま出ている＝`said`、流れからの推論（「同じ重さでもう1セット」等）＝`inferred`。どちらも `evidence` に根拠の部分を**一字一句そのまま**80字以内で抜き出す。数字が分からなければ null にして `unsure` に理由。
4. 予告か実施か・どの種目の数字か・聞き違いの疑いなど、**迷ったものは `unsure` に理由を書く**。項目に結びつかない不明点は `unclear`（理由と根拠の抜き出し）。
5. 体の痛み・怪我・診断・服薬・体調不良は `caution` にだけ書く（要約にも書かない）。疲れ・可動域・フォームの癖・意欲など**医療でない状態**は `condition`。
6. 雑談・政治・宗教・思想信条・性的指向・家族の事情・第三者の話は出さない。人の名前は出さない（「お客様」「トレーナー」と書く）。

### 5-3 出力の形（AI_SCHEMA v2・additionalProperties:false・全部 required）
```
summary:       { flow: string[] }                     ★先頭（先に推論させる）。12件・各200字まで
exercises[]:   { name, heard, note,
                 sets[]: { weight_kg: number|null, reps: integer|null, basis: "said"|"inferred",
                           evidence, unsure, note } }
condition[]    お客様の状態（医療でないもの）
caution[]      体の状態（痛み・怪我・診断・服薬・体調）
coaching[]     指導の要点
hearing[]      生活・食事・睡眠・仕事・目標・運動歴
next_actions[] 次回やること（トレーナー向け）
member_message, member_todo[]   お客様に見える文（今どおり）
unclear[]:     { text, evidence }  項目に結びつかない要確認
```
- 構造化出力（`output_config.format`）と考える処理（adaptive・thinking を省略）の併用は、今の設計39 が既に同じ形で送っている（effort だけ low→medium）。**形の中の順序で「要約が先」を作る**＝要約を書いたあとに割り振る。

### 5-4 数字の3つの状態（I76-4 を改める）
各セットを次のどれかにする（**判定は Worker・AI の自己申告をそのまま信じない**）：

| 状態 | 条件 | 画面 |
|---|---|---|
| `match`（一致） | 種目名がある・根拠に健康語が無い・`verifySet` が通る（根拠が伏せた文字起こしにそのまま在り、重さと回数がその中の数値のトークンと完全一致）・`unsure` が空 | 数字を入れた行・印なし・「入れる」が初期値 |
| `inferred`（推論） | 根拠が伏せた文字起こしにそのまま在る（健康語なし）が、数字が根拠のトークンに無い／`basis==="inferred"`／`unsure` がある。重さ 0＜w≤500 の 0.1刻み・回数 1〜100 | **数字を欄に入れたうえで「要確認」**＋理由と根拠。トレーナーが「確定」か数字を直すまで入らない |
| `nobasis`（根拠なし） | 根拠が文字起こしに見つからない・数字が範囲外・null・根拠に健康語 | **欄は空**で「要確認：数字を確かめられません」。AI の読みは小さく参考に出す（決めること D2）。打つか外すまで入らない |

- 今の `unverified` は w・r を既に返している（画面の aiunv の文に出ている）。**変わるのは「推論の値を、トレーナーの明示の1タップで記録の下書きのセットに入れてよい」こと**（今は社内メモ／捨てるだけ）。I76-4・I71 の文を改める（§9）。
- 顧客への誤った数字の守り：①要確認の行は確定・直す・外すのどれかをするまで「入れる」が押せない（§7-3）②記録の画面に入った後も ✓ は全部外れたまま（I57）＝トレーナーが ✓ して「保存する」を押したときだけ D1 に入る ③セットの数字は会員のカルテ（`MEMBER_KARTE`・いまは off）と「お客様の見え方」に出る＝**要確認のまま保存される経路を作らない**。

### 5-5 健康語・伏せる
- 健康語（AI_HEALTH＝画面の MEMO_HEALTH と同じ式）の検出の対象に `summary.flow` の各文・`condition`・`next_actions`・`unclear[].text`・`unclear[].evidence` を足す。当たった文は元の場所から消して `caution` へ（今と同じ順序：型と件数 → 検出 → 消す → 文面 → 重複は1つ → 上限）。上限は **30件**（要約から移る分が増えるため）。超えたら AI_BAD_OUTPUT（切らない）。
- **境界（決めること D3 の推奨のまま実装）**：AI に「医療でない状態は condition」と指示しても、**健康語の式に当たれば caution に倒す**（筋肉痛＝「痛」で caution）。式に当たらない「疲れ」「張り」「可動域が狭い」は condition に残る。
- 全ての出力の文に `mask` を掛け直す（今どおり）。

### 5-6 呼び出し・記録
- `effort: 'medium'`・`max_tokens: 16000`・`stream: true`（Worker の中で text の差分を足し合わせ、`message_stop` の後に1回だけ JSON.parse → 検証。**途中の出力は使わない・返さない**）。打ち切り150秒。`stop_reason` が refusal／max_tokens は今と同じコード。ストリームの error イベント・途中で切れた・壊れた JSON は AI_HTTP／AI_BAD_OUTPUT（固定のコード・中身を出さない）。
- 再試行しない（今どおり）。1回押す＝1日の回数1。
- `karte_ai_log` に列を足す（migration 0033・ALTER ADD COLUMN だけ・既定値なし・以前の行は NULL）：`n_inferred`・`n_nobasis`・`n_unclear`・`n_summary`・`fmt`（'v1'/'v2'）。`result` の値は増やさない（CHECK を作り直さない＝0018 の教訓）。`AI_BUILD` を更新。
- 日次点検（`/quota/status?karteai=1`）に v2 の件数・要確認の割合（(n_inferred+n_nobasis)/(n_sets+n_inferred+n_nobasis)）を足す。

### 5-7 入力の長さ（60分の録音に足りるか）
- 上限は今のまま：本文 128KB・`AI_TEXT_MAX` 3万字。根拠：日本語の会話は1分あたりおおよそ 150〜300字（トレーニング中は無言の時間がある）→ **60分で 9,000〜18,000字の見込み**。3万字は余裕がある見込み。
- ただし**未確認**：オーナーの約300行の書き出しの字数・Galaxy の書き出しの1行の長さ。`karte_ai_log.chars_in` と、添付の「N字を入れました」で実測してから広げるか決める。広げるなら 4.5万字・本文 192KB（3バイト×4.5万＋known）を1つの変更で（index.js の上限と画面の上限を同時に・検査で一致を固定）。
- 見出し行（「このコンテンツはAIが生成しました」等）：段階0 で添付のときに落とす（先頭3行だけ・`/AI.{0,4}(が|で)?生成/` を含む40字以下の行。正確な文言は**未確認**＝落とした行数は今どおり画面に出る）。貼り付けで入っても指示で無視させる（害は無い）。

## 6. 1回か2回か・費用・時間

### 6-1 見積もりの前提（**全部未確認・§11 で実測に置き換える**）
- 60分の文字起こし 18,000字 ≈ 入力 18,000〜23,000トークン（日本語は1字あたりおおよそ 0.8〜1.2トークン。今の `karte_ai_log` の `in_tokens/chars_in` で実測できる）。指示・形・種目の一覧 ≈ 3,000トークン。
- 価格（Sonnet 5.5）：入力 $2／出力 $10（100万トークンあたり）。考える処理のトークンは出力として課金。
- 1ドル＝150円で換算。

### 6-2 比較
| | 入力 | 出力（考える分を含む） | 1回の費用 | 時間の見込み |
|---|---|---|---|---|
| 今（設計39・low） | 約2.3万 → $0.05 | 2〜4千 → $0.02〜0.04 | **約 $0.07〜0.09（11〜14円）** | 数十秒（実測は karte_ai_log.ms） |
| **C. 1回・medium（採用）** | 約2.3万 → $0.05 | 要約1.5千＋形5千＋考える3〜8千＝1〜1.5万 → $0.10〜0.15 | **約 $0.15〜0.20（23〜30円）** | 1〜2.5分（出力の速さは**未確認**） |
| B. 2回 | ①2.3万＋②2.5万 → $0.10 | ①6千〜1万＋②6〜8千 → $0.12〜0.18 | **約 $0.22〜0.28（33〜42円）** | 2〜4分（直列） |

- 1日の上限30回なら、C で最大 約 $6／日（約900円）。担当 A が1日5回×25日なら 約 $19〜25／月（約2,800〜3,800円）。
- B でプロンプトキャッシュを使えば②の文字起こし分が安くなる（読み出し $0.10）が、①で書き込みの割増（1.25倍）があり差は小さい。加えて Anthropic 側に一時的に置く仕組みなので、同意の文面（国外の事業者・全文を残さない）との関係を確かめる必要が出る＝**使わない**。

### 6-3 判断
- **C（1回）を採用**。理由：文字起こしを送るのが1回（費用・露出・時間）、1日の回数の数え方が変わらない、「先に要約を書かせる」は形の順序と考える量で1回の中で作れる。
- **B に進む条件**：段階3 の試用で、オーナーが「要約が浅い／割り振りが要約と食い違う」と判断した、または要確認の割合が5割を超え続けた。そのときは①の出力（要約）を②に渡す形で、同じ窓口・同じ回数1で作る（回数は押した回数で数える）。
- **effort**：low→medium。高い effort は時間が延びる。medium で質が足りなければ high を1回だけ比べる（`KARTE_AI_EFFORT` は作らない＝定数。変えるときは変更として出す）。
- **時間の守り**：非ストリーミングで1〜2.5分待つと途中の回線の切断に弱い → Worker は Anthropic からストリーミングで受ける（資料の推奨）。画面は「振り分けています（2分ほど）」。**LINE の中の画面が2分待てるか・Worker から画面への応答が2分を超えて切れないかは未確認**＝段階3 の前に担当 A の端末で1回測る（§11）。

### 7-2 I71（AI の出力は保存しない・トレーナーが決めたものだけ下書きへ）をどう守るか
1. 応答は端末のメモリ（この関数の変数と画面の要素）にだけ置く。localStorage・sessionStorage・console に入れない（I63）。画面を離れる・文字を変える・別の顧客＝捨てる（今の世代の照合）。
2. 開いただけでは何も入らない。下書き（localStorage の記録の下書き）に書くのは**最後のボタンを押したときの1回だけ**（既存の `commit()` を通す）。
3. 初期値で「入れる」になるのは：一致したセット・種目名が一覧と完全一致の種目・健康語と名前の印の無いメモ（社内メモ・お客様には見えない）だけ。**要確認・お客様に見える欄（お客様へ・次回までに）・種目名が一覧に無い種目は初期値で入らない**。
4. 体の状態（caution）は**入れる操作が存在しない**（表示だけ）。健康語・名前の印（MEMO_HEALTH／MEMO_PII_WEAK）を含む文は社内メモにも入れられない（今の aiActOk と同じ）。
5. 最後のボタンが組み立てる中身は純粋関数 `reviewBuild(rv)` が作り、許されない組み合わせ（要確認が残る・caution を入れる・健康語の文を入れる・種目名が未決のセット）があれば**投げて取り込み全体を止め、下書きを変えない**（今の許可の表と同じ倒れ方）。
6. 記録の画面に入った後は今どおり：✓は全部外れたまま（I57）・「保存する」でだけ送る。
