## 0. 目的（1行）

録音の文字起こしから、AI に**まず「今日のセッションで実際に何があったか」を推論してまとめさせ**、それをもとに種目・重さ・回数・セットと種目の備考・お客様の状態・次回やることをカルテの形に割り振り、
**不明確なところに「要確認」の印を付けた下書きを1画面で一度に見せ、トレーナーが直して入れる**。AI の出力は今どおり保存しない（I71・I76-6）。

## 5. Worker（routes/karte-ai.js）

### 5-1 形式の選び方（高1・中7）
```
KARTE_AI_FORMAT   未設定（キーが無い・空文字）＝v1／"v1"／"v2"（厳密一致）。それ以外の値＝AI を閉じる
要求の client_ai_format   数値の 2 のときだけ「画面が v2 を扱える」。無い・他の値は v1 の画面
使う形式 = (KARTE_AI_FORMAT === "v2" && body.client_ai_format === 2) ? v2 : v1
```
- 不正な `KARTE_AI_FORMAT`（"V2"・"2"・"v3" 等）は、切替の段（外へ送る前・数える前）で 503 `AI_NOT_CONFIGURED` detail `FORMAT`。`k_training` の起動の印 `aiDraft` も偽になる（ボタンが出ない）。日次点検（karte-ai-health）に `formatBad` を出し warn。
- 応答の `draft.v` に**実際に使った形式**（1 か 2）。`karte_ai_log.fmt` にも実際に使った形式。
- `client_ai_format` の型が数値でない（"2" の文字列）は v1（400 にしない＝古い画面を壊さない）。知らない鍵の検査（KEYS）には足す。
- 今の liff/karte.js（キーを送らない）は、`KARTE_AI_FORMAT="v2"` でも v1 を受け取る＝今のカードの流れのまま（検査 V2-12）。

#### 5-1-2 考える量の切替（D6 保留・改訂2）
```
KARTE_AI_EFFORT   "low"／"medium"（厳密一致）。未設定・それ以外の値＝low（安い側へ倒す）
```
- v2 のときだけ効く（v1 は今どおり low）。応答の `draft.effort` と `karte_ai_log.effort` に**実際に使った値**を書く（比べるため）。
- 不正な値を閉じる（FORMAT と同じ扱い）にはしない：effort の取り違えは費用と質の差だけで、顧客に誤りを出さない。日次点検で「設定の値が low/medium/未設定以外」を warn にする。
- 空文字・"Low"／"MEDIUM"（大文字小文字の違い）・" medium"／"medium "（空白付き）は**全部 low**（前後の空白を落としたり小文字にしたりしない＝厳密一致）。日次点検の warn には出る。

### 5-2 指示（AI_SYSTEM v2・要点）
1. **最初に、文字起こし全体から「今日のセッションで実際に何があったか」を推論して `summary.flow` に時系列の短い文で書く**（言い直し・聞き違い・予告と実施の区別を前後の流れから推論してよい）。
2. その要約に沿って、種目・セット（重さ・回数）・セットの備考・種目の備考・お客様の状態・次回やること・お客様へ・次回までに を割り振る。
3. セットごとに `basis`：文字起こしにその数字がそのまま出ている＝`said`、流れからの推論＝`inferred`。どちらも `evidence` に根拠の部分を**一字一句そのまま**80字以内で抜き出す。数字が分からなければ null にして `unsure` に理由。
4. 迷ったもの（予告か実施か・どの種目の数字か・聞き違いの疑い）は `unsure` に理由。項目に結びつかない不明点は `unclear`。
5. 体の痛み・怪我・診断・服薬・体調不良は `caution` にだけ書く（要約・unsure にも書かない）。疲れ・可動域・フォームの癖・意欲など医療でない状態は `condition`。
6. 雑談・政治・宗教・思想信条・性的指向・家族の事情・第三者の話は出さない。人の名前を出さない（お客様は「お客様」、トレーナーは「トレーナー」、**それ以外の人はどうしても触れる必要があれば名前を書かずに「〔人〕」**と書く。〔人〕を含む文は画面で採用できない＝第三者の話を保存しない）。
7. アプリが付けた見出し・時刻・話者の行は内容として扱わない。

- 構造化出力（`output_config.format`）と考える処理（thinking を省略＝adaptive）の併用は、今の設計39 が既に同じ形で送っている（effort だけ low→medium）。「形の順序で要約が先に作られるか」は §16 の未確認。

### 5-4 数字の4つの状態（I76-4 を改める・改訂3 で healthHidden を足した）
| 状態（sourceStatus） | 条件（Worker が判定・AI の申告をそのまま信じない） | 画面 |
|---|---|---|
| `match` | 種目名がある・根拠と unsure と note に健康語が無い・`verifySet` が通る・`unsure` が空 | 数字を入れた行・印なし・初期値「採用」 |
| `inferred` | 根拠が伏せた文字起こしにそのまま在る（健康語なし）が、数字が根拠のトークンに無い／`basis==="inferred"`／`unsure` が空でない。重さ 0＜w≤500 の 0.1刻み・回数 1〜100 | 数字を欄に入れて「要確認」＋理由と根拠。確定か直すまで入らない |
| `nobasis` | 根拠が見つからない・数字が範囲外か null（健康語は含まない＝下の healthHidden） | **数字を欄に入れて**「要確認：文字起こしに根拠がありません」。inferred よりはっきり見分ける（下）。確定（1タップ）か直すまで入らない（D2・改訂2）。範囲外・null の数字は欄を空にする（入れられる値が無い） |
| `healthHidden`（改訂3） | **根拠か unsure に健康語**（高3）。数字の照合の結果は問わない | **欄は空**・確定ボタンは出さない・AI の数字も根拠も出さない。表示は固定文「健康の情報を含む根拠だったため、そのままは使えません」だけ（健康の内容は書かない）。トレーナーが実際に数字を打ったときだけ edited で入る |
- 今の `unverified` は w・r を既に返している。**変わるのは「推論・根拠なしの値を、トレーナーの明示の確定で記録の下書きのセットに入れてよい」こと**（D2）。
- **表示の見分け（D2）**：inferred＝薄い黄の帯＋「要確認：推論」＋理由と根拠の抜き出し。nobasis＝**濃い色の枠と帯（警告色）＋「要確認：根拠なし（文字起こしに見つかりません）」＋数字の欄も警告色の下線**。色だけに頼らず文言と印（inferred「推」・nobasis「！」）でも分ける。確定ボタンの文言も分ける（inferred「この数字で確定」・nobasis「根拠なしのまま確定」）。ダイアログは増やさない。
- 健康語に当たったセットは nobasis ではなく `healthHidden`（改訂3・再審 中4）。Worker は w・r・evidence・unsure を応答に入れない（値を null・文を空にして返す）＝画面に出しようがない。
- 顧客への誤った数字の守り：①含めてよい組み合わせを純粋データで判定（§7-4）②記録の画面に入った後も ✓ は全部外れたまま（I57）③D1 に入るのは「保存する」を押したときだけ。セットの数字は会員のカルテ（`MEMBER_KARTE`・いまは off）と「お客様の見え方」に出る＝**要確認のまま保存される経路を作らない**。

### 5-5 全自由文の表（高3・中11・改訂4 でオーナーの判断を反映）
Worker の validateDraft が、下の**全部の行**に同じ3つを当てる：①健康語（AI_HEALTH＝画面の MEMO_HEALTH と同じ式）②再マスク（I76-2 の makeMasker：登録済みの会員・トレーナーの氏名・敬称つきの名前・電話・メール。**今の動きを変えない**）③名前の印（敬称・回目・初回・体験＝PII_WEAK）。
**人名で採用を止めない（オーナーの判断 2026-11-20「人名は必ずしもマスキングする必要はない。フルネームで顧客を呼ぶケースは少ない」）**：第三者の語・人名らしい語による「採用できない（blocked）」は置かない。〔人〕を含む文も採用できる。名前の印（PII_WEAK）は v1 と同じく「初期値で採用にしない（提案を付けない）」だけで、トレーナーが押せば採用できる。

| 自由文 | 健康語に当たったら | 名前の印（PII_WEAK）に当たったら |
|---|---|---|
| summary.flow[i] | その文を消して caution へ | 初期値で採用にしない（押せば採用できる） |
| condition[i] | 同上 | 同上 |
| next_actions[i] | 同上 | 同上 |
| unclear[i].text・.evidence | text を caution へ・evidence は空に | 同上 |
| exercises[i].note | 「種目名：」を付けて caution へ | 同上 |
| sets[j].note | 同上・セットは残す（状態は変えない） | 同上 |
| **sets[j].unsure** | 同上・**そのセットを healthHidden へ** | 表示だけ（採用の対象ではない） |
| sets[j].evidence | 同上・healthHidden へ | 根拠は伏せた文字起こしの切り出し＝**再マスクだけをしてトレーナーに見せ、保存しない例外**（下の注記） |
| coaching[i]・hearing[i] | caution へ（今どおり） | 初期値で採用にしない（今の memoQuiet と同じ） |
| member_message・member_todo[i] | caution へ（今どおり） | お客様に見える欄はもともと初期値で入れない・押せば入る（v1 と同じ） |
| caution[i] | — | 再マスクのみ（入れる操作が無い） |
- 指示（§5-2-6）で「お客様・トレーナー以外の人の名前は書かず〔人〕と書く」は残す（費用も質の損も無い）。〔人〕を含む文は採用できる。
- **evidence は保存しない例外（低6）**：根拠の抜き出しは、トレーナーが数字を確かめるための表示だけに使う。再マスクだけを掛け、**下書き・社内メモ・セットのメモ・保存の payload のどこにも入れない**（reviewBuild は evidence を読まない・検査 R13 で下書きに evidence の文字列が無いことを確かめる）。
- 健康語の境界（D3 の推奨のまま）：AI に「医療でない状態は condition」と指示しても、**健康語の式に当たれば caution に倒す**（筋肉痛は「痛」で caution）。
- 画面も健康語の行は採用できない（Worker と画面の二重。画面は MEMO_HEALTH で同じ判定）。

#### 5-5-2 人名らしい語の検出（AI_PERSONISH）— 改訂4 で取りやめ
改訂3 で置いた「カタカナの未知語・よくある姓・漢字＋人の行い・第三者の語で採用できなくする」判定と、その一覧（AI_KATA_OK・AI_SURNAMES・AI_THIRD）は作らない（オーナーの判断 2026-11-20）。関門① の条件付き通過の「実装前の条件」（採用できなくなる率の基準）も不要になった。

### 5-6 呼び出し・記録（高4・中6）

#### 5-6-1 呼び出し
- v2：`effort`＝`KARTE_AI_EFFORT`（low／medium・§5-1-2）・`max_tokens:16000`・`stream:true`。v1：今どおり（effort low・8000・非ストリーミング・60秒）。
- **Worker の締切 90秒**（AbortController。Anthropic への接続の開始から）。超えたら 504 `AI_TIMEOUT`（途中の出力は捨てる）。画面の締切は 110秒（§6-4）。
- 再試行しない（今どおり）。1回押す＝1日の回数1。

#### 5-6-2 SSE の読み方（中6）
- `res.body` を `getReader()` で読み、`TextDecoder('utf-8', { fatal: true })` を **`decode(chunk, { stream: true })`** で使い、最後に `decode()` で閉じる（マルチバイトの途中で切れても壊さない・壊れたバイトは AI_BAD_OUTPUT）。
- 上限：累積 **512KB**・イベント **20,000件**・1イベント **64KB**。超えたら読み取りを止めて（reader.cancel）AI_BAD_OUTPUT。
- 順序の状態機械：`message_start`（1回だけ）→ `content_block_start`（index ごとに1回）→ `content_block_delta`（開いている index だけ）→ `content_block_stop` → `message_delta`（stop_reason・usage）→ `message_stop`（1回だけ）。`ping` はどこでも無視。**重複した start・閉じた index への delta・開いていない index・message_stop の後のデータ・未知のイベント型**は AI_BAD_OUTPUT。`error` イベントは AI_HTTP（detail は error.type の許可リストの語だけ・本文は出さない）。
- text の差分（`text_delta`）だけを変数に足す。thinking の差分は捨てる。`message_stop` が来ずにストリームが終わったら AI_BAD_OUTPUT（`detail:'NO_STOP'`）。stop_reason が refusal／max_tokens は今と同じコード。
- **生のイベント・差分・途中の文字列を console・D1・KV・応答・エラー文に出さない**（今の I76-3 と同じ。検査で console と応答と D1 の全行に身代わりの合言葉が出ないことを確かめる）。

#### 5-6-3 記録（高4：言い方を正す）
- 記録（`karte_ai_log`・access_log）は**終了処理まで届いた呼び出し**について残る（成功・失敗とも）。Worker が強制終了された（基盤の時間・CPU の上限・デプロイ等）ときは終了処理が走らず**残らない**。
- 残らなかった数は数えられる：**1日の回数（`karte_ai_usage.n`）− その日の karte_ai_log のうち回数を数えた後の行（result が ok・timeout・http_error・refused・truncated・bad_output・error）**＝「終了処理まで届かなかった回数」。日次点検（karte-ai-health）に `lost` として出し、1以上で warn。
- 列を足す（migration 0033・ALTER ADD COLUMN だけ・既定値なし・以前の行は NULL）：`fmt`（実際に使った形式 'v1'/'v2'）・`effort`（実際に使った値 'low'/'medium'）・`client_req_id`（画面が作る乱数の番号・中身なし・36字まで・形が違えば NULL）・`n_inferred`・`n_nobasis`・`n_unclear`・`n_summary`・`stream_events`・`stream_bytes`。`result` の値は増やさない（CHECK を作り直さない＝0018 の教訓）。`AI_BUILD` を更新。
- 画面は要求に `clientReqId`（今の KEYS に既にある鍵）を付け、失敗の1行に番号の末尾4字を出す（記録と突き合わせられる・オーナーが CEO に伝えれば探せる）。
- 記録が書けない（D1 の失敗）は今どおり応答を変えない（console は固定の文）。

### 5-7 入力の長さ・見出し
- 上限は今のまま：本文 128KB・`AI_TEXT_MAX` 3万字。日本語の会話は1分あたりおおよそ 150〜300字（トレーニング中は無言の時間がある）→ **60分で 9,000〜18,000字の見込み**（未実測）。`karte_ai_log.chars_in` と添付の「N字を入れました」で実測してから広げるか決める。広げるなら 4.5万字・本文 192KB を1つの変更で（index.js と画面の上限を同時に・検査で一致を固定）。
- **見出し行（低12）**：自動では消さない。`attClean` に「行全体の完全一致」の許可リスト `ATT_HEADER_LINES` を置き、**最初は空**。実物の書き出しの見出しの文言を確かめてから足す（見出しは個人情報ではないのでコードに書ける）。それまでは欄に残り、AI には「アプリが付けた見出しは内容として扱わない」と指示（害は無い）。

### 7-2 I71 をどう守るか（中9）
1. 応答は端末のメモリ（この関数の変数）にだけ置く。localStorage・sessionStorage・console に入れない（I63）。画面を離れる・文字を変える・別の顧客＝捨てる。
2. **最後のボタンの定義：「画面に並んだ採用中の全項目を一括で承認する明示の操作」**。ボタンの直上に区分ごとの採用件数（セット・種目のメモ・社内メモ・要約の有無・次回やること・お客様に見える件数）を出し、押す前に何が入るかが見える。開いただけでは何も入らない。下書き（localStorage）に書くのはこのボタンの1回だけ（既存の `commit()`）。
3. 初期値で「採用」になるのは：match のセット・一覧と完全一致の種目・健康語と名前の印（PII_WEAK）の無い**要約の文**（D1・改訂2）／種目のメモ／指導／ヒアリング／状態／次回やること（どれもお客様に見えない）だけ。**要確認（inferred・nobasis・healthHidden）・お客様に見える欄・種目名が一覧に無い種目・要確認の点・名前の印に当たった文は初期値で入らない**（名前の印の文は押せば入る＝v1 と同じ・改訂4）。
   - 要約（D1 の手当て）：①最後のボタンの直上に要約の採用文数を出す ②要約の欄は畳まずに全文を見せる（「もっと見る」にしない）③名前の印に当たった文は初期値で入れない（押せば入る）。健康語の文は Worker が caution へ移すので要約に残らない（画面でも当たれば採用できない＝二重）。
   - **D8 が決まるまでの作り**：§7-2-2 の試用モード（`AI_V2_SAVE_SCOPE` が 'trial'）。
4. 体の状態（caution）は入れる操作が存在しない。健康語に当たる行も採用の操作が無い（画面の MEMO_HEALTH で二重に見る）。人名・第三者の語では採用を止めない（改訂4）。
5. 判定は §7-4 の純粋データだけで行い、DOM の状態を読まない。

### 7-4 確認の状態（純粋データ・高2）
```
rv = {
  v: 2, gen,                                  // 応答の世代（画面の照合）
  summary: { lines:[{ text, quiet, include }], include:true },   // D1：初期値 on（quiet＝名前の印の文は初期値 off）・trial では見るだけ
  exercises: [{ id, nameStatus:'known'|'unresolved'|'named'|'excluded', name, heard,
                note: { text, quiet, include },
                sets: [{ id, sourceStatus:'match'|'inferred'|'nobasis'|'healthHidden',   // ★Worker の判定・画面で変えない
                         resolution:'unresolved'|'confirmed'|'edited'|'excluded',
                         aiW, aiR,          // AI の値（参考・変えない）
                         w, r,              // いまの欄の値
                         evidence, unsure, note:{ text, quiet, include } }] }],
  condition/next/unclear/coaching/hearing: [{ text, quiet, include }],   // quiet＝名前の印（PII_WEAK）＝初期値 off・押せば on
  member: { message:{ text, quiet, include:false }, todo:[{ text, quiet, include:false }] },
  caution: [ text ]                           // 表示だけ
}
```
- **sourceStatus は応答から一度だけ作り、以後変えない。** トレーナーの操作は resolution・w・r・include だけを変える。
- 初期の resolution：match＝`confirmed`（採用）／inferred・nobasis・healthHidden＝`unresolved`（D2：nobasis も欄に数字が入っているが未確定。healthHidden は欄が空）。
- 操作：［確定］＝`confirmed`（inferred・nobasis の両方に出る・文言は §5-4 のとおり分ける・D2）／欄の値を変えた＝`edited`（変えた後の値が範囲内のときだけ。空・範囲外は `unresolved` に戻す）／［外す］＝`excluded`／match の［採用✓］を外す＝`excluded`、付け直す＝`confirmed`。
- **含めてよい組み合わせ（これ以外は出さない）**：

| sourceStatus | 含める resolution | 含めない |
|---|---|---|
| match | confirmed・edited | excluded（unresolved にはならない） |
| inferred | confirmed・edited | unresolved・excluded |
| nobasis | confirmed・edited（D2・改訂2） | unresolved・excluded |
| healthHidden | **edited だけ**（欄が空の状態から実際に打ったとき） | unresolved・excluded（confirmed は作れない） |
- trial（§7-2-2）では、inferred・nobasis・healthHidden は**どの resolution でも出さない**（match だけ）。
- さらに種目の `nameStatus` が `known` か `named` のときだけ、その種目のセットを含める。**種目名を選び直したら（named→unresolved・別の名前へ）、配下の全セットの resolution を unresolved に戻す**（match も含む＝別の種目の数字として承認させない）。
- `reviewOpen(rv)`：unresolved のセット数＋nameStatus unresolved の種目のうちセットのあるもの＝「要確認あと N 件」。0 でなければ最後のボタンは押せない。
- `reviewBuild(rv, T)`：上の表だけで中身を組み立て、今の commit() が受け取る形（items・memos・memoNextPlan・members・todos）を返す。表に無い組み合わせ・scope の外の採用・健康語の採用・社内メモ2,000字／next_plan 500字の超過があれば**投げる**（commit は取り込み全体を止め、下書きを変えない）。

### 7-5 next_plan を運ぶ線（中10）
今は `submitMemo` が `nextPlan: ''` 固定（3154行）・`memoPending` に nextPlan が無い（3147・3210・3254行）・再送の表示（2800行）も本文だけ。次を一続きで作る：
1. **下書き**：`T.memoNextPlan`（文字列・500字まで）を足す。commit() は採用した次回やることを既存の値の後ろに改行でつなぐ（合計500字を超えるなら reviewBuild が投げる＝入れない）。記録の画面の社内メモの下に「次回やること」欄（500字・既存の値を出す・編集できる）を足す。
2. **送る条件**：今は社内メモの本文があるときだけ k_addNote を送る。**本文か next_plan のどちらかがあれば送る**（next_plan だけでも送る）。
3. **memoPending**：作る3か所（3147・3210・3254行付近）全部に `nextPlan` を入れる（本文と同じ時点の値で固定）。
4. **submitMemo**：`k_addNote` の payload の `nextPlan` に `mp.nextPlan || ''`。
5. **成功時**：`D.memoPending=null`・`D.memo=''`・**`D.memoNextPlan=''`** を同じ save で消す（片方だけ残さない）。
6. **失敗・応答不明の再送の表示**（2800行付近）：本文と次回やることを両方出す。再送は memoPending の固定した値（本文と next_plan の両方）で同じ送信番号。
7. 下書きの読み込み：古い下書き（memoNextPlan が無い）は '' として読む。
- 片方だけ保存される経路が無いこと：本文と next_plan は**1回の k_addNote の1行**（karte_notes の1行）に入る＝サーバーでは全部か無か。画面は memoPending に両方を固定し、成功で両方を消す。検査 R14。

### 7-6 出所の印を記録の画面まで運ぶ（改訂3・再審 中3）
- reviewBuild が作る下書きのセットに、AI の要確認から入ったものだけ `src` を付ける：`'inferred'`（確定した推論）・`'nobasis'`（根拠なしで確定）・`'healthHidden'`（打ち直した）。直したときは `srcEdited:true`。match のセットは付けない。
- 記録の画面は `src` のあるセットに、**保存する直前まで**印を出す：inferred＝「推」＋「AIの推論を確定」／nobasis＝「！」＋「根拠なしで確定」（警告色）／healthHidden＝「手で入力（AIの根拠は使っていません）」。直したときは「直した」を添える。行の幅に収まる短い印（ダイアログなし）。
- **保存の payload には入れない**：`buildPayload`（1295行）は weight・reps・note・assist・forced・drops を組む許可リストなので、`src` は送られない（既存の形のまま。検査 R19 で固定）。D1 にも会員のカルテにも出ない。
- 保存に成功すると下書きは消える（今どおり）＝印も消える。写す・前回の値など、下書きのセットから新しいセットを作る経路に `src` を持ち越さない（実装のときに grep で全部の経路を数え、検査で固定）。
- trial では inferred・nobasis・healthHidden は移せないので、印が出るのは full になってから（作りは今入れる）。
