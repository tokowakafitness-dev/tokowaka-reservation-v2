# 設計48 録音の文字起こしをファイルで添付する（カルテ・メモから取り込む）

2026-11-20 作成（CTO）。関門①②は CEO が回す。

## 目的（1行）
トレーナーがスマホで作った文字起こしのテキストファイルを、**端末の中で読んで**「メモから取り込む」の貼り付け欄に入れる。以後は貼り付けと同じ流れ（「読み取る」／「AIで振り分ける」）。

## 前提（実物で確かめたこと・確かめていないこと）
- 今の入口は貼り付け欄（`liff/karte.js` `trImportSub` の `textarea[aria-label="メモを貼る"]`）だけ。欄に字数の上限は無い。外へ出るのは「AIで振り分ける」（`aiSend`・`AI_TEXT_MAX = 30000` 字・Worker 側は本文128KB）だけ（I63・I76）。
- Galaxy の純正ボイスレコーダー：文字起こしを選び「共有」→「テキストファイル」で書き出せる（Samsung のサポート記事）。話者は「Speaker 1」等の見出しで分かれる（名前に変えられる）。**書き出したファイルに時刻の行が入るか・日本語の見出しが「話者 1」か「スピーカー 1」かは未確認**（実機で1本書き出して確かめる）。
- iPhone のボイスメモ（iOS 18〜）：確かな出し方は「文字起こしをコピー」＝貼り付け。.txt で共有できるという記事と、できないという記事がある（**未確認**）。→ iPhone は今の貼り付けで足りる。
- 他のアプリ（文字起こしアプリ・会議ツール）は .srt／.vtt（字幕の形）を書き出すことがある。

## 比べた手段
| 手段 | オーナー操作 | 戻せるか | 変える面積 | 判断 |
|---|---|---|---|---|
| A. 何もしない（共有→コピー→貼り付け） | 0 | ― | 0 | Galaxy は「テキストファイル」で共有するとコピーの手間が増える。1ファイルを開いて全選択してコピーは片手で難しい |
| **B. テキストファイルを端末の中（FileReader）で読み、貼り付け欄に入れる** | 0（push で出る・GAS 反映なし） | ボタンを消すだけ | `liff/karte.js` の取り込み画面に入口1つ | **採用** |
| C. 音声ファイルそのものを受け取り、こちらで文字起こし | 鍵・契約が増える | 難 | Worker・保存・同意 | **不採用**：当社に音声を保存しない・端末の外での文字起こしになる（決定0153 の送り先は Anthropic の下書きだけ）。同意の文面にも無い |
| D. .docx も読む | 0 | 可 | zip と XML の読み取りを端末に足す | **見送り**：書き出しの実例が未確認。必要が見えたら足す（いまは「テキストファイルを選んでください」と出す） |

## 作るもの（B）
- 貼り付け欄の直下に「ファイルを添付（文字起こしの .txt）」ボタン（高さ48px・幅いっぱい・片手）。押すと隠した `input[type=file]`（accept=`.txt,.srt,.vtt,text/plain`）を開く。
- 読み方（全部端末の中・`liff/karte.js` の `attKind`／`attDecode`／`attClean`）：
  1. **形式の判定**（`attKind`）：拡張子が先、無ければ MIME。`audio/*`・`video/*`・音声の拡張子（m4a/mp3/wav/aac/amr/3gp/ogg/opus/flac/mp4 等）→ 「音声は送れません」と出して**読まない**。.txt/.text → txt、.srt → srt、.vtt → vtt。それ以外（.docx/.pdf 等）→ 「文字起こしのテキストファイル（.txt）を選んでください」と出して読まない。数字だけの拡張子（「録音 2026.11.20」）は拡張子なしと見る。
  2. **大きさ**：ファイルが 1MB を超えたら読まない。整えた後、いまの欄の字と合わせて `AI_TEXT_MAX`（3万字）を超えたら**欄に入れずに知らせる**（切らない）。
  3. **文字コード**（`attDecode`）：BOM（UTF-8／UTF-16LE／UTF-16BE）を見る → UTF-8（fatal）→ だめなら Shift_JIS（fatal）→ どちらも読めない・NUL を含む（中身がバイナリ）なら「文字を読めませんでした」で欄に入れない。`TextDecoder` が無い端末も入れない（答えない側）。
  4. **時刻・話者の行を落とす**（`attClean`）：
     - どの形式でも落とす：`00:00:01 --> 00:00:04` の行・**時:分:秒**だけの行（`[00:00:01]`・`(0:01:02)` も）・`Speaker 1`／`話者 1`／`スピーカー 1`（後ろに時刻があってもよい）だけの行。行頭の `話者 1：`・`Speaker 1:`・`[00:01]`・`00:00:01 ` は外して本文を残す。
     - **.txt では分:秒だけの行（`1:30`）と数字だけの行は落とさない**：メモでは「プランク／1:30」「30」が記録そのものになり得る（落とすと記録が消える＝倒れる向きが逆）。残った時刻は欄に見えるので、トレーナーが消せる。
     - .srt／.vtt では加えて：先頭の `WEBVTT`・`NOTE`/`STYLE`/`REGION` のかたまり・時刻の行の直前の通し番号・`<v 話者>` 等のタグ・空行を落とす。
     - 名前に変えた話者の見出し（例：「田中 00:01」）は**落とさない**（形が決まらない）。AI に送るときは既存の伏せる処理が通る（I76②）。
  5. 欄に入れる：欄が空なら置く。字があれば**後ろに足す**（打った字を消さない）。入れた後は貼ったときと同じ（`ta.oninput` を呼び、前の読み取り結果・AI の応答を捨てる）。
  6. 知らせる：「N字を入れました（時刻・話者の行を M行落としました）。まだどこにも送っていません。」（落とした行数を見せる＝落としすぎに気づける）。
- 画面の注記：「添付したファイルは端末の中で読んで上の欄に入れるだけで、どこにも送りません。音声のファイルは使えません。」既存の「『AIで振り分ける』は外部（Anthropic）へ送ります」とは矛盾しない（送るのは押したときだけ）。

## 触る不変条件
- **I63**（メモの原文は端末のメモリの中だけ）：読んだ中身・**ファイル名**を localStorage／sessionStorage／console に出さない。読んでいる途中に画面を離れた・別の顧客を開いたら捨てる（世代と `cur.customerId` で見る）。添付は fetch を呼ばない。→ 守る検査 `liff-karte-attach.test.js` T1・T6。
- **I76**（AI 下書きの送信条件）：変えない。送るのは「AIで振り分ける」を押したときの1回だけ。添付の文字も AI に送られる前に既存の上限（3万字）と伏せる処理を通る。→ T6（添付だけでは k_aiDraft が飛ばない）・T7（添付の後に押すと1回だけ・本文は添付の整えた字）。

## 判定できないとき
- 形式が分からない・文字コードが分からない・大きすぎる → **欄に入れない**で理由を出す（貼り付けの道は残る）。
- 時刻か記録か分からない行（.txt の分:秒・数字だけ）→ **残す**（消すと記録が失われる。残せば目で見て消せる）。
