# 63 社内メモの上限を 2,000→4,000字に上げる

> 2026-11-26。CEO 指示（オーナー原則「数字は捨てない。細かい情報は残し、いつでも引き出せる状態」・決定0207 追記）。

## 目的（1行）
長い文字起こしを AI 下書きにしても、社内メモ（指導のメモ・その日のメモ）を削らずに入れられるようにする。

## 事実（実物で確かめたこと）
| | 値 | 場所 |
|---|---|---|
| Worker の字数 | `KARTE_LIMITS.NOTE_CHARS` 2,000（k_addNote・k_editNote・k_importDay の note） | `worker/src/routes/karte.js` |
| 画面の字数（複製） | reviewBuild の `memoMax: 2000`／取り込みのその日のメモ `note.length > 2000`／社内メモの欄2つの `maxlength: '2000'` | `liff/karte.js` |
| 表 | `karte_notes.body` に字数の CHECK は無い（migration 不要） | `0025_karte.sql` |
| **本文の上限** | **全 action の入口で 16KB（`KARTE_LIMITS.BODY_BYTES`）** | `worker/src/index.js` |
| 読み取りの重さ | 一覧は1ページ20件・概要は最新1件。k_trainingAll は社内メモの本文を読まない | `karte.js` notes / summary / trainingAll |
| GAS | 社内メモの字数の判定は無い（GAS の変更は不要） | `gas/` を grep |

## 値の決め方（10,000字にしなかった理由）
- 日本語は UTF-8 で1字3バイト。**10,000字＝30KB で、本文16KB を超える**（Worker は 413 で断る）。
- 本文の上限を変えずに入る最大：記録の画面の送り方（body だけ）で約4,900字、社内メモの画面（＋次回やること500字）で約4,400字（ID トークン約1.3KB＋鍵を引いた残り）。
- 過去のまとめ（`karte_history_digest`）も同じ理由で 4,000字。**4,000字**に揃える（12KB＋1.5KB＋トークン＋鍵＝約15KB）。
- 10,000字にするなら `BODY_BYTES` を上げる（全 action の入口の縛り＝別の判断）。CEO の指示「Worker の要求サイズは変えない」に従い、ここでは上げない。

## 変えたもの
- Worker `NOTE_CHARS` 4,000。画面は定数 `NOTE_MAX`（=4,000）1つに寄せ、上の複製4か所すべてがこれを見る。
- 過去分の取り込みのその日のメモも同じ 4,000（設計62 段3 の G6 を改める）。体の注意は 2,000 のまま（表の CHECK）。
- 取り込みは1日分（メモ4,000＋体の注意2,000＋種目）で 16KB を超えうる＝送る中身の UTF-8＋鍵128＋トークン分2,048 が 16KB を超える日は、押す前に「この日は長すぎて1回で送れません（メモか体の注意を短くしてください）」（切らない）。

## 変えていないもの
お客様へ（400字）・次回やること（500字）・体の注意（2,000字）・本文16KB・表・GAS。

## 判定できないとき
超える文は押せない（切らない）。見積もりをすり抜けても Worker が 413 TOO_LARGE（画面は「入力が長すぎます。」）＝黙って消えない。

## 戻し方
`NOTE_CHARS` と `NOTE_MAX` を 2,000 に戻す（既に入った 2,000字超の行は読めるまま。編集の保存だけが断られる）。
