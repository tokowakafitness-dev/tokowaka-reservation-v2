## 1. 守る不変条件（壊さないもの）
1. 予約・変更・取消・まとめて予約・振替・ペア・代行の**送る中身と順番**は変えない（DOM の作りを変えても、値を読む要素の id と onclick の処理は残す）

3. **予約できる最終日・週送りの上限**（bookingHorizon・maxWeekOffset）はそのまま（liff-week-horizon.test.js）
4. **4言語**（日本語・英語・中国語 簡体・繁体）：画面の文言は t() と data-i18n を使い、新しい文言は4言語とも足す。言語の切り替えは今の場所に残す
5. **戻る操作**：各画面の data-back（端末の戻る・横スワイプ・LIFF を閉じない）はそのまま（liff-back-nav.test.js）
6. **トレーナーの見た目（body.staff）と読み込み中（body.booting）**と食い違わない。会員の見た目は body.staff の無いとき（＝今の既定）として書く。トレーナーが代行で会員の画面を使い回すときは body.staff の見た目が勝つ
7. サーバー由来の名前・日時は**文字として**入れる（HTML にしない）
8. viewport（meta）は変えない

## 改訂1（Codex 関門① 1周目の反映・2026-11-06）

### 1-1 作り方の不変条件を強める（重大1・4・5）
- **on(id, fn) で処理を付けた静的なボタン（homeReserve・homeMyRes・batchToggle・batchClear・batchGo・confirmBtn・confirmCancel・confirmHome・prevWeek・nextWeek・backToTrainer・weekHome・toHome・myResBack・doneClose・registerBtn）は DOM の要素そのものを置き換えない。** 見た目は CSS と、親の付け替え（appendChild で移動）・class の追加・子の追加だけで変える。置き換えが要る所は作らない
- **同じ画面の data-back の DOM の順番を変えない**（s-week は backToTrainer → weekHome の順＝端末の戻るは「トレーナーを選び直す」）。見た目の並びは CSS（order）でも変えない
- **確認画面の選択肢（cfAtt・cfKind・cfPay）は、読む・書くを cfOptions の中に限定する**（document.querySelector → opts.querySelector）。見た目用の複製は作らない。cfOptions の「破棄→生成→処理の付け直し」は一体のまま

### 1-2 言語の切り替えで予約の内容を変えない（重大2・高9・中10・中11）
- **既存の不具合を C1 で直す**：確認画面で言語を切り替えると openConfirm が最初から走り、useTransfer・attendeeCount・packKind・packKindExplicit が初期化される＝送る中身が変わる。→ openConfirm(slot, keep) に分け、言語切替の描き直し（_repaint）は keep=true で**選択の状態を保ったまま文言だけ描き直す**（選択肢の取得もやり直さない＝前回の応答を state に持つ）
- 完了画面：表示の材料（担当・日時・種別）を state に持ち、_repaint で描き直す（言語切替で旧言語が残らない）
- トレーナー選び・自分の予約：言語切替は、取得済みの結果を state に持って描き直すだけ（再通信しない）
- 会員登録の送信中の表示：送信中かを state に持ち、applyI18n の後も「登録中…」を出す

### 1-3 トレーナーの見た目が効く範囲（重大3）
- body.staff の見た目を保証するのは、代行・変更で使う s-trainer・s-week・s-confirm と s-tadmin だけ。s-home・s-register・s-myres に入ったら外す（今の実装どおり・意図的）
- **会員の新しい既定の CSS は、今の会員の CSS の位置（body.staff の指定より前）に書く**＝同じ強さなら後ろの body.staff が勝つ。会員の指定に !important を使わない

### 1-4 文字として入れる対象（高6）
- 名前・日時に限らず、**サーバーから来た値はすべて**文字として入れる（textContent／要素を作る）。t() は変数をそのまま差し込むので、t() の結果を innerHTML に入れる所は差し込む値を先に文字に直す（_sEsc）
- 対象（今の素通し）：loadTrainers のトレーナー名、自分の予約の dateLabel・trainerName、履歴の dateLabel・trainerName・statusLabel、チケット期限（p.expire・singleExpire）、振替の期限（nextExpireLabel）

### 1-5 まとめて予約（高7）
- C1 では処理を変えない（タイムアウトの照合は通常の確定だけにある＝既存のまま）。検査で今の振る舞い（確認→読み込み画面に移る＝二度押せない・例外はエラー画面・一部成功の知らせ）を固定する

### 1-6 状態ごとの表示（高12）
| 状態 | 表示 |
|---|---|
| オンボード期間 | 残数を出さず案内・「＋ 予約する」を隠す（今どおり） |
| 契約が使えない | 案内文（今どおり・コーラルの注意） |
| 超過 | 超過の行（コーラル）・残りはマイナス表示（今どおり） |

| 振替がある | 「振替 n回 〇/〇まで」（コーラルの印・期限） |
| 確認：ペアのみ／ペアと通常／残り1人数回 | 今の選択肢と既定を変えない（来店人数・使うチケット・お支払い方法の3つ。名前は「使う回数」ではなく今の見出しのまま） |
| 確認：時間変更・振替のモード | 選択肢を出さない・取得を待たずに確定できる（今どおり） |
| 確認：選択肢の取得に失敗 | 今の再試行の表示 |
| SLOT_TAKEN の後 | 確定ボタンを戻さない（今どおり） |
| まとめて予約：0件・一部成功・代行 | 今どおり |
| 読み込み失敗・エラー | エラーのカード（新しい見た目） |

### 1-7 検査を強める（高8）
- 入口から：起動の判定（未登録→登録・登録済み→ホーム・トレーナー→管理・失敗→エラー）を、本番の分岐の部分を取り出して通す。ホーム→トレーナー→週→確認→確定をボタンの click で通す（on() の配線ごと）
- 送る中身の比較（身代わりの api で受けて、作り替え前の版と同じ中身か）：通常（packKind 空）・ペア（pair・1名/2名）・確認画面の振替（line_makeTransferReservation）・キャンセル後の振替モード・会員の変更（line_changeReservation）・オーナーの無料変更・代行（proxy）・まとめて予約（通常・代行）・キャンセル・タイムアウトの照合（通常・変更・代行）
- **言語：各辞書（ja・en・zh・zh-Hant）が新しい文言の鍵を自分で持つ**（日本語への置き換えで隠れないように）。動的な画面（ホーム・確認・完了・自分の予約）を出した状態で言語を切り替え、旧言語が残らないこと
- **確認画面で選択を変える→言語を切り替える→送る中身が同じ**（不具合の再発防止）
- 英語の長い文言のはみ出しは jsdom では測れない＝オーナーの実機確認（英語に切り替えて見る）を関門③の前提にする

## 改訂2（Codex 関門① 2周目の反映）

### 2-1 確定の送信中・照合中は、言語を切り替えてもボタンを戻さない（重大）
- 確定の送信中とタイムアウトの照合中は state.confirmBusy=true（送信を始めた時に立て、成功・はっきり断られた・SLOT_TAKEN の扱いが終わった時だけ下ろす。照合できなかった＝不明のままは下ろさない＝今どおり押せないまま）
- setConfirmEnabled() は confirmBusy 中は必ず押せない
- openConfirm(slot, true) は送信中・照合中のボタンの文言・押せない状態・confirmErr を初期化しない
- 確定ボタンの処理の先頭でも confirmBusy を見る（二重の守り）
- 検査：予約の送信中に言語切替→押せないまま・予約の送信は1回／照合の1回目と再試行の間に言語切替→押せないまま・再送なし／照合できなかった後に言語切替→押せないまま

### 2-2 取得の失敗の文は、鍵で持って今の言語で出す（高）
- state.optError は翻訳済みの文字ではなく state.optErrorKey と置換の値で持ち、描くときに今の言語で t() する
- サーバーが返す r.message は「サーバーの文」として扱い（訳さない）、文字として出す（innerHTML にしない）
- 検査：日本語で取得に失敗→英語に切り替え→英語の文になる

### 2-3 keep（取得をやり直さない）の条件
- keep=true は言語切替の描き直しからだけ呼ぶ
- 取得結果に {startISO, customerId, proxyMode, changeMode, transferMode} の印を持たせ、今の予約の対象と一致するときだけ使う（違えば取得し直し、_optSeq を進める）
- 取得中に言語切替：_optSeq を進めない・optReady=false のまま（押せない）・元の応答が来たら今の言語で描く・応答の時点でも対象の一致を確かめる
- 検査：取得中に言語を何度切り替えても line_getBookingOptions は1回
