### 4-2. 境界（誰の時計で決めるか・I93 の追記）

- **境界＝JST の今月1日から数えて2か月前の1日**（今月を含む3つの暦月）。例：11/26 → 9/1。12/1 になった瞬間に 10/1 へ動く＝9月分が「3か月より前」へ移る。月替わりのまとめ（D3'）と単位を揃えるため、毎日動く「今日から90日」は採らない。
- 計算は **Worker の時計だけ**（`windowStart(nowMs)`・JST）。★**各要求の冒頭で `nowMs` と `boundary` を一度だけ求め、その要求の中の全 SQL・`older`・`pendingMonths`・`monthsAll`・応答の `boundary`・カーソルの発行と検証に同じ値を使う**（関門① 第2周 中2：月替わりの瞬間をまたぐ1つの要求の中で境界が割れない）。初回の応答に `boundary: 'YYYY-MM-01'` を返し、画面はその値だけを使う（端末の時計で決めない＝端末の日付がずれていても境界は割れない）。
- 段2 の「まとめ待ち」・段4 の「既定で外す」も同じ `boundary` を使う。

### 5-2. 表と窓口（I96 案）

- migration 0037（`CREATE TABLE IF NOT EXISTS` だけ・既存の表に ALTER しない）：
  ```sql
  CREATE TABLE IF NOT EXISTS karte_month_digest (
    customer_id TEXT NOT NULL,
    month       TEXT NOT NULL CHECK (length(month) = 7 AND month GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]' AND substr(month, 6, 2) BETWEEN '01' AND '12'),

    updated_at  INTEGER NOT NULL,
    deleted_at  INTEGER,

  );
  ```
- 書く：新しい窓口 `k_saveMonthDigest`（`customerId`・`month`・`body`・`rev`・`origin`）。名前が `k_save*`＝isKarteWrite（Origin・iat の守り）・runWrite（回数・二重送信・全部か無か）。許可表 `perms.js` に `trainer`。共有の範囲（I47）。

### 5-3. 月替わりの「まとめ待ち」（誰が・いつ）

### 5-4. トレーニングの記録の「まとめ」（M4・保存しない）

- 3か月より前のトレーニングは、全期間の推移と自己ベスト（§4-4）に加えて、畳んだ行の上に**月ごとの1行**「2026年8月：8回・主な種目 ベンチプレス／スクワット・最高 80kg×5（スクワット）」を出す。
- 作り方：初回の応答に `monthsAll: [{month, sessions, top, best}]`（境界より前の月だけ・新しい順・上限36＋truncated・集計ごとの状態 `agg.months`）。生きた記録から読むたびに作る＝保存しない・AI を使わない・同意に関係しない。定義（関門① 中5）：
  - `sessions`＝その月の生きた session の数（数字の無い種目だけの回も数える）
  - `top`＝その月の生きた session に出た種目（セット〔`karte_tr_sets`〕か数字の無い種目〔`karte_tr_exercises.done_only=1`〕）を、**出た session の数**（`COUNT(DISTINCT session_id)`）の多い順・同数は種目名の順で3つまで
  - `best`＝本セットで無理やりでない行（ドロップ・補助の回数は数えない＝I66）から、重さ→回数→早い日→session_id の順で1つ（`{exercise, w, r, d}`）。数字の行が無い月は null

## 7. 段4 整形済みの過去メモを日付ごとに取り込む

- 共有のプロンプト（CEO が書く）の出力の形を「読み取る」の書き方に合わせる：**日付の行（年つき推奨 `2025/5/10(土)`）→ 種目の行（`ベンチプレス 60×10 60×8`）→ 自由文**。日付の行どうしの間が1日分。
- 流れ：貼る → 日付の行が2つ以上なら「日付ごとに分けて入れる（N日分）」→ 日の一覧（新しい日が上・1行44px以上）→ 行を押すとその日の文だけで今の「読み取る」→ 記録の画面で ✓ → 保存 → 一覧に戻り［済］。
- 日付の判定は「読み取る」と同じ関数（`memoDateLine`）。前置き・読めない日付は一覧に出し、黙って捨てない（I64）。
- 日付の行かどうかの判定は `memoDateLine`（今の `MEMO_DATE` と同じ・「読み取る」と共有）、年の決め方は**別の関数 `resolveYear`**（関門① 中8：責務を分ける）。順と範囲を固定する：
  1. 日付の行に年がある → その年
  2. **年だけの行**（`^\s*(\d{4})\s*年?\s*$`）→ その行より後、次の年だけの行までの日付の行に当てる
  3. 日付の行に曜日がある（`MEMO_DATE` の括弧の中の1文字だけ）→ **今日の年から6年前まで**で曜日が合う年。候補が**ちょうど1つ**のときだけ採り「曜日から推定」。0個・2個以上は**決まらない＝日付を選ぶまで取り込めない**
  4. どれも無い → 今の `memoDate` を呼ぶだけ（今年・今日より後なら去年）・「年は推定」。並び（新しい順でも古い順でもない）と食い違えば一覧の上に注意
  - どの道で決めた日付も、最後に `memoReal`（実在）と「今日以前」を通す（通らなければ決まらない）
- 同じ日の知らせ：初回の `allDates`（`[{d,n}]`）で「記録あり N件」・止めない。`allDates` が null なら「確かめられません」。
- **境界（`boundary`）より前の日**：確認の画面で社内メモへ入る欄を既定で外す（押せば入る＝止めない）。一覧の下に「〇月のまとめを書く」（段2 の書く画面へ・その月の日の文の自由文を上に並べる＝トレーナーが写して直す）。
- 原文・日の文・［済］は画面のメモリの中だけ（I63）。AI は使わない（AI のボタンも出さない）。
