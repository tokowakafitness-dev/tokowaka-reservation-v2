### 4-2. 境界（誰の時計で決めるか・I93 の追記）

- **境界＝JST の今月1日から数えて2か月前の1日**（今月を含む3つの暦月）。例：11/26 → 9/1。12/1 になった瞬間に 10/1 へ動く＝9月分が「3か月より前」へ移る。月替わりのまとめ（D3'）と単位を揃えるため、毎日動く「今日から90日」は採らない。
- 計算は **Worker の時計だけ**（`windowStart(nowMs)`・JST）。★**各要求の冒頭で `nowMs` と `boundary` を一度だけ求め、その要求の中の全 SQL・`older`・`pendingMonths`・`monthsAll`・応答の `boundary`・カーソルの発行と検証に同じ値を使う**（関門① 第2周 中2：月替わりの瞬間をまたぐ1つの要求の中で境界が割れない）。初回の応答に `boundary: 'YYYY-MM-01'` を返し、画面はその値だけを使う（端末の時計で決めない＝端末の日付がずれていても境界は割れない）。
- 段2 の「まとめ待ち」・段3 の取り込みの「直近3か月／3か月より前」の数え方も同じ `boundary` を使う（初回の k_notes／k_training の応答の値）。

### 4-3. 要求の形（WIP の4つの形に `older` を足した5つ）

| 形 | 鍵 | 返すもの |
|---|---|---|
| 初回 | 形の鍵が全部無い（k_training：`cursor`・`older`・`before`・`sessionId`／k_notes：`cursor`・`older`・`before`・`month`） | **境界以後の回**（新しい順・上限100。超えたら `more:true`・`nextCursor`＝**R の系列**）＋ `boundary` ＋ `older`（境界より前に生きた回が1つでもあるか・`LIMIT 1` の読み）。★全期間の集計は別の窓口 `k_trainingAll`（§4-4・関門② で分けた） |
| 3か月より前の最初のページ | `older: true` だけ | Worker 自身の境界より前の20回（`session_date < boundary`＝境界の日を含まない）。`nextCursor` は **O の系列** |
| ページ送り | `cursor` だけ | 系列ごとに20回ずつ。**R は全ページで `session_date >= 境界` を守り、境界より前へは進まない**（境界以後を読み切ったら `more:false`）。O は境界より前だけ |
| 前回の読み足し | `before` だけ（D 当日を含まない） | D より前の20回（`nextCursor` は返さない＝この形からページ送りしない）。I59 の「前回」専用 |

- ★**カーソルは2つの系列に分け、発行したときの境界を持たせる**（関門① 第1周 中3）：`R|<境界>|<日付>|<作成時刻>|<id>`（3か月以内）／`O|<境界>|<日付>|<作成時刻>|<id>`（3か月より前）。Worker はカーソルの境界が**今の境界と違えば 409 `BOUNDARY_MOVED`**（月が替わった＝画面は初回から読み直す）。R と O の集合は交わらない（R は `>= 境界`・O は `< 境界`）。形の違いは 400（WIP の 400 のまま）。★**M のカーソルは境界を持たない・月替わりの 409 の対象外**：M は月そのものを固定し、対象の月は要求の時点で常に境界の月より前＝月が替わっても境界の外へ出たままで、対象から外れることが無い（ただし M の月が実在しない・書式違いは 400）。WIP の3要素のカーソル（`YYYY-MM-DD|作成時刻|id`）は WIP にしかなく main に出ていない＝互換の対象外で、受け取ったら 400（関門① 第2周 軽4）。

- `k_notes` も同じ（`sessionId` の形は無い・代わりに `month` がある＝初回・`older`・`cursor`（R／O／M）・`before`・`month` の5つ）。初回は境界以後の指導メモ（上限100）＋`boundary`＋`older`。段2 で月のまとめと「まとめ待ち」を初回に足す。

### 4-4. 全期間の集計（I94）

★**別の窓口 `k_trainingAll`**（要求は customerId だけ・形の鍵は 400・許可表は k_training と同じ）。画面は一覧を描いた後に呼ぶ（関門② 中2：重い会員で集計が Worker の時間・CPU の天井に当たっても、一覧は先に返っている）。推移のセットは `DISTINCT` で読み、同じ重さ×回数の繰り返しを Worker へ運ばない。

`bestAll`（会員と同じ関数 `bestAllQuery`・同点は早い日・上限+1 で truncated）／`seriesAll`（session を LIMIT 1001 で選び日の境で打ち切る・`seriesFrom`）／`allDates`（`[{d,n}]`・LIMIT 2001）。集計ごとに `agg` の状態（ok／truncated／unavailable）・失敗は null。`k_trainingAll` の1回で返す（k_training の応答には含めない）。画面は使えないとき「直近◯回の中」と書く（全期間と言わない）。

### 4-5. 画面

- トレーニングのタブ：「前回」→「種目ごとの推移（全期間）」→「日別の記録（直近3か月）」の下に、`older` が真なら畳んだ行「**3か月より前の記録を見る（〇月より前）**」（44px）。押すと `older: true` で20回を読み、以後は O のカーソルで「もっと前を見る（20回ずつ）」。境界以後が100回を超えたときの続きは、日別の記録の中の「続きを見る」（R のカーソル）で、3か月より前には入らない。409 `BOUNDARY_MOVED` なら「月が替わりました。開き直します」で初回から読み直す。各行は今の日別の記録と同じ（［編集］［削除］は作者かオーナー）。
- 指導の履歴：直近3か月のメモ → 段2 の「月ごとのまとめ」→ 畳んだ「3か月より前のメモを見る」（同じページ送り）。
- 読めなかったら「読めませんでした（もう一度押してください）」・読んだ分は残す（WIP どおり）。

### 4-6. 1件の読み直し・前回の読み足し（WIP のまま）

- ［編集］を押すたび・直す画面の復元のたびに `sessionId` で読み直す。置き換わっていれば replaced_by を5段までたどる（各段で会員・論理削除・形を確かめる）。画面は extra → deleted「もうありません」→ broken「新しい版を確かめられませんでした」→ それ以外「読めませんでした」の順だけで出し分ける（I95）。送り直し待ちの直しかけがあれば古い id のまま今の流れ。
- 記録の画面・直す画面の日付 D が、つながって読んだ回の最も古い日以前なら `before: D` で D より前の20回を読み足して「前回」を出す。失敗は「前回：読み込めていません」（I59 の改め）。

### 5-1. 比べた手段（P0：原本は日ごとの記録。まとめはそれを束ねた別の文）

### 17-2. 決め方（I98 の改め）
- **鍵**：名前の決定待ち＝`n:<名前>`／R2〜R10 で読める行＝`r:<文>`／それ以外の行＝`l:<種類>:<文>`（文は NFKC・空白をそろえた形）。決めた値は画面のメモリの `S.dec` に1つだけ（日の配列には持たない）。取り込む全部の日（入れる日・済んでいない日）に効く。日の中身のカードも同じ鍵を書き換える。

  | 未決 | 出さない（前の名前の決めることで止まる） |
