### 4-2. カーソル（I93 案）

- 並び順を**全部で一意**にする：`ORDER BY session_date DESC, created_at DESC, session_id DESC`（`k_notes` は `note_id`）。
- 要求の鍵 `cursor`（文字列 `YYYY-MM-DD|<created_at の整数>|<id>`）。条件は
  `session_date < d OR (session_date = d AND (created_at < c OR (created_at = c AND session_id < id)))`。
- `PAGE+1` 件読んで、21件目があれば `more:true` と `nextCursor`（20件目の値）を返す。
- `cursor` が形に合わない（実在しない日付・整数でない・id の形が違う）→ **400 BAD_REQUEST**（黙って1ページ目を返さない＝同じ記録が2回並ぶのを防ぐ）。
- 既存の `before` は**残す**（旧画面は送らないが、外すと旧の検査を壊す）。`cursor` と `before` を両方送ったら 400。
- `cursor`・`before`・`sessionId` が**全部無ければ**今と同じ1ページ目（応答に `more`・`nextCursor` が足されるだけ）。旧画面は `customerId` だけを送る（`liff/karte.js` 2249）＝初回として扱われる。
- ★**要求の4つの形**（関門① 第2周 中1・第3周 中2）：**初回**＝`cursor`・`before`・`sessionId` が全部無い／**ページ送り**＝`cursor` だけ／**前回の読み足し**＝`before` だけ／**1件の読み直し**＝`sessionId` だけ（`extra` と `trace` だけを返し、20回・集計・まとめ・`noteDays` は返さない）。2つ以上を同時に送れば 400。全期間の集計（§4-3）・まとめ（§5-2）・`noteDays`（§6-5）は**初回だけ**に返す（読み足し・［編集］のたびに重い集計を走らせない）。`k_notes` は `sessionId` を持たない＝**3つの形**（初回＝`cursor`・`before` が無い／ページ送り＝`cursor` だけ／旧互換の `before` だけ）で、まとめ・`noteDays` は初回だけ。

### 4-3. 全期間の集計（1ページ目だけ・I94 案）

`k_training` の**初回（`cursor`・`before`・`sessionId` が全部無い要求）の応答にだけ**次を足す：

| 鍵 | 中身 | 作り方 |
|---|---|---|
| `bestAll` | 種目ごとの自己ベスト `{exercise, w, r, d}` | 会員の `bestQ` と**同じ関数**（`member-karte.js` の SQL を `lib/` の関数に出して両方から呼ぶ）。本セット・無理やりでない（I66）・重さ→回数→**早い日**。種目数の上限は引数（トレーナーは 200・会員は今の50）で、**上限+1 を読んで `bestTruncated`** を返す（会員の応答の形は変えない＝会員側は今どおり上限で切るだけ） |
| `seriesAll` | 日ごと・種目ごとの推定1RM の最大 `{d, exercise, e1rm}` ＋ `seriesFrom`（含めた最も古い日） | ★**先に session を新しい順に `LIMIT 1001` で選ぶ**（`ORDER BY session_date DESC, created_at DESC, session_id DESC`）。1001件未満＝全部採る・打ち切りなし／1001件目が1000件目と**同じ日**＝その日を丸ごと外す／1001件目が別の日＝先頭1000件を採る／1001件目があれば `seriesTruncated:true`。**採る session が決まってから**、その id の本セット（無理やりでない）を全部読む＝含めた日の値は欠けない。今の `e1rm()`（`karte.js`）で日×種目の最大を取る。打ち切ったら `seriesTruncated:true` |
| `allDates` | 生きた session の日付と件数 `[{d, n}]`（新しい順・上限 2,000 日） | `SELECT session_date, COUNT(*) … GROUP BY session_date ORDER BY session_date DESC LIMIT 2001`。2,001行目があれば落として `datesTruncated:true`。段3 の「この日は記録があります（N件）」に使う |

- ★**集計ごとに状態を返す**（関門① 重大4）：`agg: { best: 'ok'|'truncated'|'unavailable', series: …, dates: … }`。集計は1つずつ try で包み、失敗した集計の値は **`null`（空配列にしない）**・`agg` は `unavailable`。集計が失敗しても1ページ目の20回は今どおり返す（`k_training` 全体を落とさない）。
- 画面：種目ごとの推移・自己ベスト・種目の一覧（チップ）は `bestAll`／`seriesAll` から作る。**鍵が無い（古い Worker）・`null`・`unavailable` のときは今の計算（読んだ回の中）に戻し、見出しに「直近◯回の中」と出す**（全期間と言わない）。`truncated` のときは「◯月◯日から」（`seriesFrom`）・「一部の種目」と出す。段3 は `allDates` が `null` なら「この日の記録があるか確かめられません」と出す（「記録なし」と言わない）。
- **同点の扱いを会員と揃える（F4）**：トレーナーの自己ベストも「早い日（初めて達成した日）」にする。今の表示の日付が変わり得る（同じ重さ×回数を何度も出した種目は、最後の日→最初の日）。CTO の判断（自己ベストの日付は「初めて出した日」の意味で、会員とトレーナーで違う日が出るのは誤り）。オーナーが逆を望むなら両方を新しい日に揃える。
- 呼ばれる回数：トレーニングのタブを開くたび1回（今と同じ回数）。読む行は会員1人の全セット＝F18 から最大で数千行。D1 の1日の読み取り上限（500万行）に対して小さい。

### 4-4. 画面

- 日別の記録の最後に「もっと前の記録を見る（20回ずつ）」（44px・`more` が真のときだけ）。押すと `cursor` で読み、**同じ session_id は足さない**（重複の除去）で今の配列に足して描き直す。失敗したら「読めませんでした（もう一度）」を出し、読んだ分は残す。
- 足した古い記録にも［編集］［削除］が今の条件（作者かオーナー・I87/I90）で出る＝**入れた過去分が窓の外で直せない問題（調査 §3）が解ける**。
- 「前回の記録から写す」（trPickSub）は今どおり読んだ回から（変えない）。
- 指導の履歴（`k_notes`）にも同じ「もっと前を見る」とカーソルを付ける（応答に `more`・`nextCursor`）。

### 4-5. 窓の外の記録を直す画面の復元（F7・I95 案）

- `k_training` に鍵 `sessionId` を足す（§4-2 の「1件の読み直し」）：その session（その会員・生きている）を `extra` で返す。
- ★**直して置き換わった session を新しい版へたどる**（関門① 中7・第2周 中3）：各段で
  ```sql
  SELECT json_extract(before_json, '$.replaced_by') AS replaced_by
    FROM karte_revisions
   WHERE table_name = 'karte_tr_sessions' AND row_id = ? AND reason = 'edit'
   ORDER BY changed_at DESC, id DESC LIMIT 1
  ```
  を読み、各段で次を全部確かめる：今の sid がその会員の session／中間の古い版は論理削除済み／`replaced_by` が session ID の形／次の session も同じ会員／**最後の1つだけが生きている**。たどるのは5段まで。循環・自分を指す・6段目・途中の欠け・形の違いは「たどれない」（応答は `extra:null`・`trace:'broken'`）とし、本当に消えた（edit の控えが無い）`trace:'deleted'` と検査で区別する。見つかれば `extra` に新しい版・`replacedFrom:<古い id>`。読むのは共有の範囲（I47・`readSection` の見張りのまま）。［編集］を出すか・直せるかは今どおり画面の作者／オーナーの条件と `trainingEdit`、保存時は I87 の見張り。
- `extra:null` のときの `trace`：本当に消えている（edit の控えが無い）＝`deleted`／**最初の sid がその会員の session でない**＝`deleted`（どの会員の記録かを応答で区別しない）／たどった先が他の会員・循環・6段・途中の欠け・形の違い＝`broken`。
- ★**［編集］を押すたび、および直す画面の復元（ログインの取り直し・戻る・進む）のたびに**、`sessionId` を付けて読み直してから直す画面を開く（関門① 第2周 中4：一覧に残った古い版をそのまま開かない）。
- ★画面の出し分け（関門① 第3周 中1）：`extra` あり＝開く／`trace:'deleted'`＝「この記録はもうありません」／`trace:'broken'`＝「新しい版を確かめられませんでした。開き直して日別の記録で確かめてください」（消えたと言わない）／通信・応答の失敗・`trace` の鍵が無い（古い Worker）＝「読めませんでした（もう一度）」。`extra` で見つかれば開く（`replacedFrom` があれば「ほかで直された新しい版を開きました」を1行出し、直す下書きは捨てて読み直す＝古い版の下書きを新しい版に当てない）。★判定は `extra` の有無ではなく上の順（extra → deleted → broken → それ以外は「読めませんでした」）だけで行う。
- ページ送りの途中で別の画面が古い記録を直すと（I87：新しい session は日付と created_at を写すので、同じ日・同じ作成時刻の中で id だけ変わる）、今の画面には古い版が残る・新しい版が足されないことがある。**受け入れる**：(1) ［編集］は押すたびに読み直してたどるので、古い版の内容で直す画面が開かない (2) 書き込みは rev と生存で守られ、古い版で上書きはできない（I87 の見張り・`karte.js` 891 付近）(3) 一覧の表示が古いままになるのは、消しの成功（読み直す・今どおり）か、直しの成功画面の「一覧を見る」（今は押したときだけ読み直す）か、開き直しまで。誤った書き込みは起きず、表示の古さだけが残る。

### 4-6. 過去の日付を入れるときの「前回」（F6）

- 記録の画面・直す画面の日付 D が、読んだ回の最も古い日より前（または同じ）なら、**既存の `before: D`（SQL は `session_date < ?`＝D 当日を1件も含まない）**で D より前の20回を読み足す（関門① 重大1：カーソルを流用すると D 当日が20件あれば読み足しが全部 D 当日で埋まり「前回なし」になる）。ページ送りは `cursor`、前回の読み足しは `before`、と**鍵を分ける**（両方送れば 400）。I59（「前回」は入力中の日付より前の直近1回・読んだ回の中）は**読む窓を D の前へずらす**形に改める。
- 読み足しが失敗・まだのときは「前回：読み込めていません」と出す（「前回なし」と言わない）。

### 5-2. 中身と守り（I96 案）

- ★**`k_summary` には足さない**（関門① 中9：概要は profile を丸ごと返す＝開くたびに2,000字の全文が端末へ行く）。読みは **`k_notes` の初回（`cursor` も `before` も無い要求）の応答に `digest: {text, until, rev}`** を足し、指導の履歴を開いたときだけ返す（SQL で2列と rev だけを名指しで読む）。保存は `k_saveProfile` のまま（rev は profile の rev）。検査で「`k_summary` の応答に past_digest が無い」も固定。

- 健康の言葉：まとめは自由文＝I55 のとおり健康情報の置き場所ではない。入力欄の真下に「痛み・診断・服薬は『注意すること』へ」を出す（今の自由文と同じ・サーバーで意味は判定しない）。

## 6. 段3 日付ごとの取り込みと過去メモ用の AI

### 6-1. 比べた手段（調査 §6 の再掲・要点）

A'（画面で日付ごとに切って1日ずつ今の取り込みへ）を採る。A（AI が複数日を1回で返す）は形・検証（I76）・確認の画面（I71・設計49/50/51）の作り直しになり、誤った分け方が match で通る経路が増える。C（一括の作業依頼）はトレーナーの確認を通らない（I71・I76-⑥ に反する）。

### 6-2. 流れ（画面）

1. 記録のタブ →「メモから取り込む」→ 貼る（今の画面）。
2. 貼った文に**日付の行が2つ以上**あれば、「読み取る」の前に「**日付ごとに分けて入れる（N日分）**」を出す（今の1日分の読み取りも選べる＝今の振る舞いを残す）。
3. 日の一覧（新しい日が上）：各行に「2025/5/10(土)・12行・［記録あり 1件］・［済］・［メモはまとめへ］」。1行 44px 以上。行を押すとその日の文だけで今の取り込み（読み取る／AI）を開く。
4. 取り込み→記録の画面で ✓→保存 → 保存の成功で日の一覧に戻り、その行に［済］。次の日へ。
5. 一覧の下に「これより前の N日分からまとめを作る」（段2 のまとめの書く画面へ。AI が使えるなら「AI で下書き」）。

### 6-3. 切り方（I98 案）

- 日付の行の判定は**「読み取る」と同じ関数**（`MEMO_DATE`＋`MEMO_DATE_NOYEAR_DOT` の判定を1つの関数 `memoDateLine(line)` に出し、`parseMemo` と分割の両方が呼ぶ）。分割した1日分を `parseMemo` に通したとき `second_date` が出ないことを検査で固定。
- 最初の日付の行より前の文（前置き）は「日付の無い前置き（N行）」として一覧の先頭に出す。どの日にも自動で足さない。「この日に足す」「入れない」をトレーナーが選ぶ（**黙って捨てない**＝I64）。
- 日付として読めない行（実在しない・未来）は、その行から次の日付の行までを「日付を決めてください」の行にする。日付を選ぶまで取り込めない。
- 年の決め方（優先順・行ごとに一覧に出す）：
  1. 日付の行に年がある → その年（今どおり）
  2. その行より前に**年だけの行**（`2025` `2025年`）がある → その年
  3. 日付の行に**曜日**がある → 今日以前・6年前までで曜日が合う年。**候補がちょうど1つのときだけ**その年にし、行に「曜日から推定」を付ける。0個・2個以上なら「日付を決めてください」（候補の年をボタンで出す）。受け付ける曜日の書き方は今の `MEMO_DATE` と同じ「括弧（半角・全角）の中の1文字」だけ（`5/10 土`・`(土曜日)` は曜日なしとして 4 へ）。曜日の書き方を広げるなら `MEMO_DATE` ごと広げ、「読み取る」と分割で同じ式を使う
  4. どれも無い → 今の `memoDate`（今年・今日より後なら去年）。このとき一覧の行に「年は推定」を付ける。
  - 4 の行が並び順と食い違う（日付の並びが新しい順でも古い順でもなくなる）なら、一覧の上に「年が推定の日があります。日付を確かめてください」を出す（止めない）。
  - 行を長押しせずタップで「日付を直す」（日付の欄・max=今日）。
- 同じ日付が2回出たら、別々の行のまま出す（まとめない）。

### 6-4. 同じ日の知らせ（止めない）

- 段1 の `allDates` に同じ日があれば行に「記録あり N件」。押せば今どおり入る（同じ日に2回分けて保存する正しい使い方を壊さない・調査 §5）。
- 同じ一覧の中で［済］の行をもう一度押したら「この日は今入れました。もう一度入れますか」を1回だけ出す（二重の取り込みの防止・ダイアログはこの1か所だけ）。

### 6-5. 20回の境界の表示（D2）

- ★境界の決め方（関門① 重大2）：`k_notes` の初回の応答に **`noteDays`＝指導メモのある日（`GROUP BY session_date ORDER BY session_date DESC LIMIT 20`・件数でなく日）** を足す。画面は `noteDays` と一覧の日付の**集合和**（同じ日は1回）を新しい順に並べ、先頭20日に入らない一覧の日に［メモはまとめへ］を付ける。`noteDays` が読めない（古い Worker・失敗）ときは［メモはまとめへ］を付けず、一覧の上に「20回の境界を確かめられません」と出す（推測で付けない）。
- ［メモはまとめへ］の日を取り込むときは、確認の画面で社内メモへ入る欄を**既定で外す**（トレーナーが押せば入る＝止めない）。トレーニングの数字は入る（D1）。
- 「20回」の数え方は**指導メモのある日の数**（1日に複数のメモがあっても1回）。

### 6-6. 状態の置き場所（I63 を守る）

- 貼った原文・分けた日の文・［済］の印は**画面のメモリの中だけ**（モジュールの変数・持ち主＝トレーナー×会員）。localStorage・sessionStorage・console に出さない。会員が変わった・画面を閉じたら捨てる。
- 戻ってきたら貼り直す（［済］は消えるが、`allDates` の「記録あり」で入れた日は分かる）。
- 1日分を記録の画面へ入れた後は、今の下書き（`karte_tr_draft_v1`）の仕組みのまま。

### 6-7. 過去メモ用の AI（I97 案）

**要求の鍵を1つ足す**：`client_source`（`KEYS` に追加）。値は無い（今の録音）／`'memo_day'`／`'memo_digest'` の厳密一致。それ以外は 400（送らない・数えない）。

`AI_SYSTEM_V2_MEMO_DAY`

### 6-8. 残す回数（当日の録音を止めない）

## 11. 個人情報

## 12. オーナーに確かめたい業務の規則（CEO へ）

1. **20回の境界が動いたとき**：新しい記録が増えて、1回ずつ入れた過去分が21件目より前へ押し出されたら
   (a) 1回ずつのまま残し「もっと前を見る」で見る（まとめは書いた時点のまま）← **推奨**（状態が増えない・誰も畳む作業をしなくてよい）
   (b) トレーナーが折を見てまとめに畳み、1回ずつの方は消す
2. **過去メモの AI の回数**：店全体1日30回の中で
   (a) 過去メモにも使う。ただし当日の録音のために毎日10回は残す ← **推奨**（費用が増えない・録音が止まらない）
   (b) 上限を上げて過去分にも十分に使う（費用が増える）
   (c) 過去分には AI を使わない（読み取るだけ）
3. **過去分を会員に見せるか**（いまは `MEMBER_KARTE=off` で誰にも見えない。on にした日から）
   (a) 過去分のトレーニングの数字は会員の自己ベスト・日別に出てよい。過去の日付の「お客様へ」は作らない ← **推奨**
   (b) 過去分は会員に出さない（記録に「過去分」の印を持つ仕組みが要る＝状態が1つ増える）
