## 改訂2（2026-11-10・関門① 1周目の指摘を反映）★本節が上の表より優先

Codex 関門①（スレッド 01a1c433-4775-71b1-9d32-593eb6271845）：要修正。最重要は
「数値にした行も計画の一覧に出る」という前提が実装と合わないこと。自動で読んだセットは
`res.items[].sets` に直接入り（karte.js addChunks）、計画（makePlan）は `pending` のうち `propose` があるものだけを見る。

### A. 新しく読む数字は、すべて「下見つきの決定待ち＋提案」にする（items に直接入れない）
- 対象：R2・R4・R5・R7・R8・R10（今まで1件ずつだった入力を数値にするもの全部）
- 形：`pending { kind:'rule', rule:'R2'…, lines, text, parsed:{ exercise, sets:[…] }, item: idx, propose:'addset' }`
  （既存の `kind:'paren'` と同じく、下見の数値を持つ決定待ち）
- 計画の一覧に「原文 → 『〇〇』に 55kg×5 を足す（R10）」の形で出る。「この内容で決める」で初めてセットになる
- build()：`act:'addset'` は `res.items[p.item].sets` に parsed.sets を**全部か無か**で足す。
  足すと 1種目10セット・合計60段を超えるなら**1つも足さず**、そのカードを「上限のため入れられません」で残す
- 確定前は items に入れない＝二重に入らない。計画を閉じれば未決定のまま
- R1（+N＝補助）・R6・R9・R11 は既存どおり（R1 は現状の自動、R6/R9/R11 はメモの提案）

### B. 判定の順番（健康・名前を先に）
1. `MEMO_PII_STRONG`（行頭の名前＋敬称）→ 既存どおり伏せて「捨てる」を提案
2. **`MEMO_HEALTH`・`MEMO_PII_WEAK` を行全体で見る → 該当行には R2〜R10 を一切当てない。** 原文全体を提案なしの1件ずつに（数値だけ抜くこともしない・I71）
3. sealed 中は R2〜R10 を当てない
4. R9・R11（次・次回・相談の言い方）を R10 より先に判定 → 該当すれば行全体をメモの提案
5. その後に R2〜R10

### C. 各規則の境界
- **R2**：形は行全体が `<色><チューブ|バンド>×N(+M)?`。色は かな/カナ/漢字 1〜4字（数字・+・×を含まない）。
  直前が sealed でない確定済みの種目のときだけ。直前が名前の決定待ちなら当てない。
  登録済みの種目名と一致・前方一致する名前なら G2（種目）を優先。セットのメモは `<色><チューブ|バンド>` だけ。N・M は 1〜100、外れたら全体を1件ずつ
- **R3**：**一括の計画に入れない。** カードで1件ずつ「〇〇を種目にする＋残りの文をその種目のメモ」を選ぶ。
  文中の登録済み種目名がちょうど1つ・1回のときだけ提案。held の名前・suggestKnown だけの名前は候補にしない。
  作った種目にセットが無ければ、残りの文は既存どおり社内メモへ（種目名を付ける）
- **R4**：`<セット>(<括弧の中>)` で括弧が1つ・閉じている・中に健康語が無いときだけ。中身はそのセットのメモ。それ以外は既存どおり paren の決定待ち
- **R5**：行全体が `×N(+M)?自重` に完全一致のときだけ（G6 の例外）。メモ「自重」
- **R7**：行全体が `×Nずつ M種類`（N 1〜100・M 2〜10）・直前が sealed でない確定済みの種目のときだけ。画面の行き先に「『〇〇』に重さなし×N を M セット（M種類のバリエーション）」と書く。上限を超えるなら全体を残す
- **R8**：行頭またはセット区切りの直後の `a+b×N(+M)?` で、a と b が**数値として等しい**（0.1刻み・0〜500）・N 1〜100。前後に別の文字があれば読まない。1行に複数あれば行全体を1件ずつ。左右が違えば**一部も読まず**全体を1件ずつ
- **R10**：重さ（数字＋kg|キロ）と回数（数字＋回|レップ|rep）の組が**行にちょうど1組**のときだけ（`自重で10回` は重さなし）。
  2組以上（「55キロで5回、次60キロで3回」）は**行全体を提案なしの1件ずつ**（区切りの文法は検証で実例が集まってから足す）。
  「〜を3セット」は同じセットを3つ（2〜10・上限超えは全体を残す）。全角数字は NFKC で直す。漢数字は読まない
- 「いきます」は予告＝実施の確認ではない → だから A により**必ず確認の一覧を通す**（自動では入れない）

### D. 足す検査（§4 に追加）
- 共通：健康語・名前の印・敬称を含む行は R2〜R10 が items にも提案にもならない／sealed 中に付かない／
  失敗時に一部の数値だけ入らない／上限で一部だけ入らない／計画を開いただけでは dec も items も変わらない／
  原文が保存・通信・console に出ない（I63）
- R2：種目あり・なし・sealed・直前が名前の決定待ち・`赤チューブ×10+5`・色に数字を含む形
- R3：「スクワットの時と同じ意識で」が一括の計画に出ない・種目名2つは提案なし・held は候補にしない
- R7：N=0/101・M=1/2/10/11・既存セットとの合計で上限超え・前後に文字
- R8：`16+16×10`・`16+12×10`（部分も入らない）・`16.0+16×10`・`500+500×100`・範囲外・前後に文字・複数
- R9〜R11：`次67.5×`・`次回70×5`・`次のセットで55キロ5回いきます` は数値にならない／`55キロで5回いきます` は確定前に items に入らず、確定後に1セットだけ入る／2組の文は1件ずつ／漢数字・全角・`REP`
- 壊す検査：R10 を自動のセットに戻す・健康の判定を後ろに回す・R3 を計画に入れる・R8 の左右一致を外す・R7 の上限の全部か無かを外す、のどれでも落ちること

### E. MODEL への反映（実装時）

## 改訂3（2026-11-10・関門① 2周目）★改訂2より優先

### F. セットの順番と宛先は「通し番号」で持つ（添字を使わない）
- 読み取りの中で、セットになり得るもの（自動で入るセット・`paren`・`addset`・`exnote` が運ぶセット）すべてに、
  読んだ順の通し番号 `sq`（整数・行順→行内の順）を振る
- `setnote` の宛先は添字 `setAt` ではなく、対象セットの `sq`（`setSq`）で持つ
- build()：種目ごとに「自動のセット＋決まった paren/addset/exnote のセット」を集め、`sq` の小さい順に並べ直してから `set_no` を振る。
  `setnote` は `setSq` が一致するセットに付ける。そのセットが入っていなければ（捨てた・上限）既存どおり種目名を付けて社内メモへ
- ★**既存の不具合も同時に直る**：いまの `act:'set'`（paren を数値にする）は末尾に push しており、
  「55×10(+3更新)」の下に 57.5×8 があると順番が逆になる（karte.js build の `base[p.item].sets.push`）
- 検査：addset の前後に普通のセット／同じ位置に addset が2件／paren を数値にしたときの順番／addset を入れた後の setnote の宛先

### G. 上限は計画を作るときに数える（入らないものは計画に入れない）
- makePlan() の写しに、種目ごとの仮のセット数と仮の合計段数を持ち、pending の順に足していく。
  足すと 1種目10・合計60 を超える addset は**計画に入れず、未決定のまま残す**（カードに「上限のため入れられません」）
- カードで addset を選んだときも同じ検査をし、超えるなら dec を付けない
- 既存の下書き（T.items）との合算の超過は、従来どおり「記録の画面に入れる」で取り込み全体を止める（カード単位の判定は取り込みの中だけ）

### H. R10 の種目の決め方
- 行頭が登録済みの種目名（autoKnown・held でない・ちょうど1つ）＋区切り（、 , 空白）なら：
  その種目は**既存の G2 と同じく種目として入る**（名前を言った＝種目は確か）。数字は addset（確認の一覧を通す）。
  addset を捨てたら、その種目は「実施のみ」で残る（記録の画面に見えるので黙ってではない）
- 行頭に種目名が無い：直前の確定済み・sealed でない種目へ。無ければ行全体を1件ずつ
- 行頭の名前が held・suggestKnown だけ・複数一致：行全体を1件ずつ（数字も読まない）
- 行頭の種目名と直前の種目が違う：行頭を採る（言った名前が優先）
- 検査：「ベンチプレス、55キロで5回いきます」（実際にお願いする言い方）・名前なし・held の名前・2つ一致

### I. R3 の残りの文
- 種目名を抜いて前後をつなぐことはしない。**原文の全体を**その種目のメモにする（不自然な連結を作らない・黙って捨てない）

### J. 健康・名前の判定の範囲（指摘6）— ★採らない（理由）
- 指摘：健康語のある行は既存の G 規則・R1 も含めて数字を読まないこと
- **採らない**：I71 が止めるのは「健康の言葉（文）を自動でどこかに入れること」。同じ行の重さと回数は健康の情報ではなく、
  設計40 で「数値は入り、健康の文は提案なしの1件ずつ」として関門②を通過した振る舞い（P64〜P89）。
  これを変えると、いま自動で読めている実メモの行が読めなくなる（後退）
- ただし**新しい規則（R2〜R10）は保守的に行全体を止める**（改訂2 B のまま）。新旧で扱いが違うことを MODEL の I71 の説明に明記する

### K. 敬称の無い氏名（残る危険・受け入れ）

- 受け入れる理由：計画の一覧は**貼ったトレーナー本人の画面にだけ**出る（保存しない・送らない・会員に出ない・I63）。
  R10 の数字以外の部分はどこにも保存されない。R4 の括弧の中はセットのメモ（会員に出ない）。設計40 §7 と同じ種類・同じ判断
