## 2. 誤り a〜e の原因（該当行）と直し方

### a. 回数が null・根拠は在るのに「根拠なし（文字起こしに見つかりません）」
- 原因：`worker/src/routes/karte-ai-v2.js` 278〜283行。
  ```
  const wv = w === null ? null : (wOk(w) ? w : null);
  const rv = rOk(r) ? r : null;
  const inRange = rv !== null && (w === null || wv !== null);
  if (at >= 0 && inRange) { nInf++; return { status: 'inferred', ... } }
  nNob++;
  return { status: 'nobasis', ... }
  ```
  根拠が見つかっても（`at >= 0`）、回数が null・範囲外なら `inRange` が偽になり nobasis に落ちる。画面は nobasis を一律に「要確認：根拠なし（文字起こしに見つかりません）」と出す（`liff/karte.js` 2911行）＝**分類が文言と食い違っている**。
- 同じ並びの別の誤り（同時に直す）：278行で**範囲外の重さ（600kg 等）が null になり、自重の null と区別できない**。画面は `aiW == null` を「自重」と描く（2909行）・`reviewFromDraft` は w が null なら欄を空＝自重にする（2226行）＝範囲外の重さが自重として確定できる。
- 直し方（分類を正す・§4-3）：**nobasis は「根拠が文字起こしに見つからない」だけ**にする。根拠が在れば数字が欠けていても inferred（欠けた数字は null＝画面では `?`＝入れない）。重さは「自重」と「分からない」を別の値で返す（`bw`・§4-2）。

### b. AI が根拠を言い直して照合に落ちる
- 原因：根拠の照合は `maskedSquashed.indexOf(ev)` の完全一致（`karte-ai-v2.js` 274行・`karte-ai.js` verifySet 172行）。squash は NFKC と空白の詰めだけ（`karte-ai-v2.js` 189行）。AI が聞き違いの語を正しい語に直す・句読点を足し引きすると、1字でも違えば見つからない。
- 直し方（§4-4）：①指示文で「根拠は原文の文字をそのまま写す。聞き違い・言い間違いも直さない」を強める。②**空白と句読点（、。・「」『』！？!?…）の違いだけ**を無視して位置を探し、見つかった位置の**原文の切り出し**を根拠として使う（verifySet にはその原文を渡す＝数字の照合は今と同じく原文の上で行う）。**語の置き換え（聞き違いの語と正しい語）までは緩めない**＝見つからなければ今どおり nobasis。`.`・`,` は数字（2.5）を壊すので無視しない。

### c. 雑談がヒアリングに入る
- 原因：コードでは判定していない（判定できない）。指示文 `AI_SYSTEM_V2` 72行に「趣味・旅行などの雑談は書かない」はあるが、誘い・予定の話が「生活」と読まれた。

### 4-2 形（AI_SCHEMA_V2）：セットに `bodyweight` を足す
```

```
- 理由：今の形では weight_kg の null＝自重しか表せず、「重さが分からない」を表せない（AI は推測の数字を入れるしかない）。CEO の短縮案「不明は null」を正しく使うには自重を別の値にする必要がある。

- **新しい正規表現を作らない**。1つのかたまり（1セット）を `memoSets`（1503行）で読む。`memoSets` は `memoSet`・`MEMO_SEG`（1345行）・`MEMO_SEG0`・`memoW`（0〜500・0.1刻み・0＝自重）・`memoInt`（1〜100）・ドロップ（`+重さ×回数`）・補助（`+回数`）・無理やり（`(できない)` 等6語）をそのまま使う。
- `rvParseLine(line)` の手順：
  1. NFKC。`×`・`x`・`*`・`✕`・`✖`・`+` の前後の空白を詰める（`50 × 10` を1かたまりに）
  2. 空白・`、`・`,` で区切って、かたまりの並びにする（かたまり＝1セット＝色チップ1つ）
  3. かたまりに `?` を含む → **skip（入れない）**
  4. 先頭の `自重` の直後が `×` 等 → `自重` を外す（`自重×10` → `×10`＝MEMO_SEG0 の自重）
  5. `memoSets(かたまり)` が最後まで読め（`memoFull`）・**読めたセットがちょうど1つ**・括弧は無理やりの語だけ（`paren == null`）・ドロップが `MEMO_LIMITS.drops`（3）以下 → set。それ以外 → **bad（書き方が読めない）**
- 実行で確かめた（`memoSets` を NFKC した文字に当てた結果）：`20×5`・`50x10`・`55×5+40×8`（ドロップ1）・`×10`・`0×10`（自重）・`50kg×10`・`50 × 10`・`2.5×12`・`50×10(できない)`（無理やり）は読める。`自重×10` はそのままでは読めない（→ 手順4で `×10` にする）。`20×?`・`?`・`600×5`・`50×0`・`50×10×3` は読めない。`50×10(左)` は paren が残る（→ bad）。`55×5、50×5` は2セット（→ 手順2で先に分ける）。
- 書き方の案内（見出しの横・1行）：「書き方：50×10　自重×10　?＝入れない（× は x でも可）」。
- 数字を打つ欄は `inputmode="text"`（× と ? を打つため）。`autocomplete="off"`・`data-nodirty="1"`（今と同じ）。
