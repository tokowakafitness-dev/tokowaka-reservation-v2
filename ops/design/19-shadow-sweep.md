# 19 shadow の母数を毎日まとめて取る（sweep）（設計）

> 起草：2026-10-14／**第8版・関門①（9往復）②（4往復）通過・実装済み（未反映）**（決定0084）
> オーナー承認：「進めてください」「引き続き進めて」（2026-10-14）

## 0. 結論

1. **毎日1回、GAS が残数の写しを送り終えた直後に、対象の会員全員の「写し」と「D1」を比べる**（入口名 `sweep`）。比べる本体（`runShadow`）・記録・鮮度の条件は既存のまま
2. ★**作り直さない。食い違いは全部「食い違い」として記録し、合格を止める**。偽の食い違いが起きにくい時間（**5〜7時**＝通常は4時の全件同期が終わっている・予約がほぼ入らない・日付の境目から遠い。★同期の成功は前提にしない＝世代・待ち行列・写しの鮮度で会員ごとに安全側へ倒す）に比べる。食い違いが出たら CEO が中身（写し・D1 の値と世代）を見て、タイミングか本物かを判定する
   - 第2版「時刻で同じ状態かを判定」：不成立（D1 の source_at は D1 が受け取った時刻で、Google 側の変更時刻ではない）
   - 第3版「食い違ったら作り直して2回目だけ記録」：不成立（**D1 の本物の破損を作り直しで直して、合格に数えてしまう**）
3. ★**合格の判定を2つに分ける**：①値の確認（期間で累積・sweep を含む）②配線の確認（顧客の3つの入口がそれぞれ1回以上）。最終の合格は両方

## 2. 設計

### 2-1. Worker：`GET /quota/shadow-sweep?limit=4&after=<id>&skip=<id,…>`
- 合言葉（`requireSecret`）。`LB_D1_REMAIN_MODE !== 'shadow'` なら `{ ok:true, skipped:'MODE_OFF' }`
- 対象：`calc_contract_rows` の会員（合格の分母と同じ SQL）を ID 順に `limit`（1〜4）件
- `skip` の会員（GAS の二重書きの待ち行列に残っている＝台帳の変化が D1 に届いていない）は呼ばない（記録しない）→ `dw_queued`
- それ以外は会員ごとに順番に（1名ずつ try）：`readHomeDiag` → `runShadow(env, { customerId, entry:'sweep', copyDiag, nowMs, targetMs:nowMs, lang:'ja' })`
  - ★比べ方・記録・見送り（写しの鮮度・世代・枠）は runShadow の既存どおり。食い違いもそのまま記録される
- 返す：`{ ok, customers, done:{completed, diffs}, why:{理由:件数}, retry:[完全ID], next }`。会員IDは末尾4桁。`next`・`retry` は内部の窓口用の完全ID
  - ★会員ごとに `{ id:末尾4桁, done, why }` を返し、内部用に `completedIds`・`terminalIds`・`retry`（完全ID）を返す
  - 分類（列挙の漏れを避ける形）：`done === true` → `completedIds`（完了に数える）／`why === 'no_slot'`（その日の枠を使い切った）→ `terminalIds`（当日は再試行しない・完了にも数えない・理由を残す）／`bad_args` 等の実装の誤り → `terminalIds`（異常として数えて warn）／**それ以外の done:false はすべて `retry`**（`dw_queued`・`behind`・`slot_failed`・`version_changed_during_shadow`・写しの鮮度・読み取りや記録の失敗）
- `only=<id,…>`（最大4）を渡したら、その会員だけ同じ処理（再試行用）

### 2-3. GAS：押し出しの後・ロックの外で
- `_pushToEdgeHomeImpl` は `{ ok, result }` を返す。`pushToEdgeHome` は `_edgeLocked` の戻り（＝ロック解放後）で**成否にかかわらず必ず** `_edgeMaybeShadowSweep({ pushOk })` を呼ぶ（try で包み、例外を外へ出さない）。★期限切れ・前日の掃除・月初の心拍は押し出しの成否と関係なく要る。**比べる処理だけ**を押し出しが成功したとき（`pushOk === true`）に限る
- 条件：JST **5〜7時**／今日まだ終えていない（`LB_SHADOW_SWEEP_DAY`）
- ★月の1日は動かさず、`LB_SHADOW_SWEEP_LAST` に「計画的な見送り（MONTH_FIRST）」を心拍として残す（見張りが誤って鳴らないように）
- **状態は3つに分ける**：`LB_SHADOW_SWEEP_AFTER`（一覧のカーソル）／`LB_SHADOW_SWEEP_RETRY`（その日の再試行の会員）／`LB_SHADOW_SWEEP_DAY`（完了した日）
- ★**処理の順番**（`_edgeMaybeShadowSweep` は 7時以後も含め押し出しのたびに必ず呼ぶ）：
  1. JST の日付を読む
  2. 保存された状態の日付が今日でない（前日以前）なら、未完了を `expired` として `LB_SHADOW_SWEEP_LAST` に記録し、前日の `AFTER`・`RETRY`・リースを消す
  3. 月の1日なら `MONTH_FIRST` を記録して終わる
  4. 今日 7時を過ぎていて未完了なら `expired` を記録して終わる（★時間帯の判定より先）
  5. 5〜7時でなければ終わる
  6. `pushOk !== true` なら比べ始めずに理由を残して終わる（写しが新しくない）
  7. リースを取って今日の sweep を処理する
- ★**同時に1つだけ**：sweep 専用のリース `LB_SHADOW_SWEEP_LEASE = {token, until(10分後)}`。始めるときだけ短く ScriptLock を取り、有効なリースがあればこの回は見送る。Worker との通信中は ScriptLock を持たない。`AFTER`・`RETRY`・`DAY` を書き換えるときは短い ScriptLock の中で「自分の token が今のリース」を確かめてから書く。終わったら自分の token のときだけリースを消す。強制終了したら期限後に次の回が引き継ぐ
- 1回の実行では：再試行の会員を先に（`only=`・4名ずつ）→ 時間が残れば一覧の続き。再試行の集合は **`RETRY = (いまのRETRY ∪ 応答.retry) − completedIds − terminalIds`**（HTTP 200 や retry に無いことだけで外さない）
- **その日を完了にするのは「一覧を最後まで回った」かつ「再試行の集合が空」のときだけ**
- 7時を過ぎても完了しなければ、完了の印を付けずに `LB_SHADOW_SWEEP_LAST` に `expired`（対象人数・比べ終わった人数・見送った人数と理由）を残し、翌日の再試行は捨てて一覧の最初から
- ページを回す（最大12ページ・4名ずつ）。**1ページごとに残り時間を見て**、足りなければ `LB_SHADOW_SWEEP_AFTER` に続きを残して次の回（30分後）に再開
- **一覧を最後まで回り、かつ再試行の集合が空になったときだけ** `LB_SHADOW_SWEEP_DAY=今日`。結果の要約を `LB_SHADOW_SWEEP_LAST`（時刻・比べ終わった数・食い違い・見送った理由）
- `skip`：呼ぶ前に二重書きの待ち行列の会員IDを読んで渡す
- 時間：GAS の実行開始から **300秒を絶対の締切**。新しいページを始めるのは残り30秒以上あるときだけ
- 例外を外へ出さない

### 2-4. 合格の判定を2つに分ける（Worker の集計＋GAS の表示）
- `/quota/status?shadow=1&from=YYYY-MM-DD`（★期間。省略時は今日だけ＝今と同じ）。`day BETWEEN from AND today` で集計
  - ★人数は期間全体で `COUNT(DISTINCT customer_id)`（日ごとに数えて足すと重複する）。入口ごとの回数も期間全体の `SUM`
- 判定：
  - ①値：期間の比べ終わった回数 ≥ 100 ／ 比べ終わった会員 ≥ 36 ／ 食い違い 0（sweep を含む全入口）
  - ②配線：`boot`・`compat_member`・`compat_home` が**それぞれ** 1回以上（sweep は数えない）
  - 合格＝①かつ②。★入口0回の警告は合否に関係なく**いつも**出す
- 期間の起点は**食い違いの原因を潰した日**（今回は sweep を始めた日）。作業依頼で `from` を渡す

### 2-5. 見張り
- 点検：shadow が on なのに `LB_SHADOW_SWEEP_LAST`（完了・期限切れ・計画的な見送りのどれでも）が26時間より古い → warn
- 点検：直近の sweep で「比べ終わった人数 < 対象人数」→ warn（対象・比べ終わった・見送ったの人数と理由を出す）。`expired` も warn

## 3. 量
- 1日1回 × 41名 × 約10文 ＝ 約410文／日。書き込みは食い違いが無ければ1名数行 → 約200行／日（上限10万行）
- 1ページ4名 ≒ 40〜50文（食い違いが多い最悪でも1名の記録は最大51行＝batch 1回）
- GAS：1日1回、押し出しの後ろに 10〜30秒。時間が無ければ翌回（30分後・7時まで）へ

## 3-2. 残るもの（受け入れる）
- 5〜7時の間に予約・取消・契約の手直しが入ると、偽の食い違いが記録されうる。**合格は止まる**（安全側）。CEO が中身を見て、タイミングと確かめられたら期間の起点を更新する
- 偽の一致：入力が違っても比べる値が同じなら一致と数える。shadow が測るのは「顧客に出る値が同じか」なので受け入れる

## 3-3. 食い違いが出たときの手順（CEO）
1. `remaining {shadow:true, day:…}` で、どの項目が・写しと D1 でいくつか・世代を見る
2. その会員のその時刻前後に予約・契約の変化があったか（`remaining {date:…}`・二重書きの記録）
3. 変化があった＝タイミング → 記録して期間の起点を翌日に更新／変化が無い＝本物 → 原因を直すまで切り替えない

## 4. 変えないもの
- 比べ方・鮮度の条件（10分）・枠の上限・世代の確認
- 顧客に返す値（写しのまま）。sweep は観測だけ
