## なぜ
トレーナーはセッション中、スマホ（LIFF）を片手に持って記録する。いまの画面は「セッションが終わってから、まとめて書き写す」形で、
次の3つの理由で速く入れられない。
1. **前回の内容を呼べない**。毎回、種目を選んで重量・回数を一から入れる
2. **入力の途中が残らない**。保存するまで端末にも残らない（退避は「トークンが古い」で断られたときだけ）。LINE を閉じたら消える
3. **種目は固定12＋「その他」の自由入力だけ**。その顧客がよくやる種目が上に来ない

参考は2つ：トレカル（保存済みの1ファイルを読んだ＝事実）と、筋トレMEMO（App Store の説明文と公式サイトだけ＝画面は未確認）。

## 1. 参考アプリの記録の仕組み（事実だけ）

### 1-1. トレカル（根拠：/tmp/claude-501/trekaru/m.html の関数）

**データの持ち方**
- 入力中のセッション `SESS = {client, date, template, part, exercises:[], memo, editId}`（`initSession`）
- 種目 `{name, part, unit('回'|'秒'|'分'), sets:[{w, r, done}], plan:{sets, reps, rest}}`（`exFromName`・`planToSess`）
- 保存後の記録 `{id, date, template, part, exercises:[{name, part, unit, sets:[{w, r}]}], memo}`（`completeSession`）。
  ボード経由の保存だけ、セットに `rpe`・`rest`・`note`、セッションに `cond:{sys, dia, vas, note}`（血圧・痛みVAS）が付く（`boardComplete`）
- **★セッション画面の保存（`completeSession`）は w・r しか残さない**。RPE・休憩を入れる欄は**ボード（`renderExl` の2段目）にしかない**。
  詳細表（`openTrainingDetail`）は列 ['セット','重量','回数','RPE','休憩','メモ'] を出すが、セッション画面から記録した分は RPE・休憩・メモが「—」になる
- 顧客ごとの種目設定 `PCUST.get(顧客, 種目) = {tools, form, note}`。note の入力欄の見出しは「個別メモ・痛み・禁忌」（`openExerciseCustomize`）
- メニュー（雛形）`MDB`：`{id, name, purpose, level, part, exercises:[{name, sets, reps, rest, unit}], client}`。client が空＝全顧客共有、入っていれば専用（`saveCurrentAsMenu`・`openTemplatePicker`）
- 種目の辞書 `EXERCISE_LIB`（部位 ['胸','背中','脚','肩','腕','腹','有酸素'] ごとに種目と目安回数）＋自作の種目 `XDB`＋自作の部位 `CATDB`
- 端末に全部保存（IndexedDB/localStorage）。入力中は `persistDraft` が**入力のたびに**顧客ごとの下書き（`DDB`）へ保存

**操作の流れ（セッション中）**
1. 顧客を選ぶと、当日の予定→その顧客の下書き→新規、の順で開く（`renderMenu`）
2. 「メニューを選択」（`openTemplatePicker`）の先頭に **「前回のセッションを複製」**（`duplicateSessionToToday`）。前回の各種目を、前回のセット数・重量・回数で復元し、✓は外した状態で置く。その下に「おすすめ」「最近使用」「すべて」
3. 種目カード（`buildExerciseList`）：手順番号・部位の色・**「前回 日付・最大セット」**（`prevSummary`）・目標（セット×回・休憩秒）・この人向けの設定・回/秒/分の切替・セット行（重量 kg × 回数・✓・×）
4. **「セットを追加」は直前のセットの重量・回数を複製**して足す（`buildExerciseList` の addset）
5. 新しい種目を足すと、1セット目に**その顧客のその種目の前回ベスト**が入る（`exFromName`→`setFromPrev`→`prevBest`）
6. 種目を足す画面（`openAddExercise`）：検索・部位カード・よく使う種目（固定5つ）・名前順/部位順・**複数選んでまとめて追加**・無ければ新しく作る
7. 並べ替えはつまんで動かす（`attachDrag`）か「↑上へ/↓下へ」（`openExerciseMenu`）
8. 「セッションを完了」（`completeSession`）：**✓が1つも無い種目は記録しない**・空のセットも記録しない。カードは✓が無いと赤枠（未実施の目印）
9. 完了後に「今日のメモ・日誌（任意）」をタグ付きで促す（`openPostSessionNote`）

**見る側**：日別／種目別／サマリー（MAX重量・推定1RM・合計レップの開始比と推移）／部位別のセット配分（`renderTrainingLog`・`renderTrainingByExercise`・`renderTrainingSummary`・`renderTrainingParts`）。
1件の詳細で総重量・最大重量・合計レップ・推定1RM・自己ベストの行（`openTrainingDetail`）。推定1RM は `w*(1+r/30)`（`est1RM`・回数の上限なし）。CSV・PDF の書き出し（`buildTrainLogReport`）

**無いもの**：**休憩タイマーは無い**（カウントダウン・振動・休憩中の表示の文言も処理も見当たらない）。スーパーセット・ウォームアップの区別も無い。

### 1-2. 筋トレMEMO（出所：**筋トレMEMO・App Store の説明文と公式サイト**。画面は未確認）
- 種目を部位ごとに追加・削除、部位を自由に追加（「胸筋（上部）」など）、種目の検索・登録
- セットごとに重量・回数・**補助の有無**。kg と lb
- **前回のトレーニング内容をコピー**
- **セット間の休憩タイマー**
- RM の自動計算
- 有酸素運動の記録
- 種目ごとの履歴・グラフ、**部位ごとに前回からの経過日数**（例「脚は8日ぶり」）
- 週のボリューム（棒グラフ）※レビューで報告されているだけ・未確認
- for Professional：顧客の状態と指導履歴をチームで共有、**来店時に加えて顧客の自主トレや一言コメントも蓄積**、体組成、アンケート、分析
- 画像保存・LINE などへの共有、ヘルスケア連携（詳細不明）

## 4. データと窓口の変更案

### 4-1. S（変更なし）
- S1〜S5 は k_training の応答（直近20回のセッションとセット）だけで組める。**migration も窓口も変えない**
- 「前回」は**直近20回の中で**探す（それより前にしかない種目は「前回の記録なし」）。画面に一言書く
- 保存は今までどおり k_addTraining に、✓のセットだけを送る

### 4-2. A（migration 0027 案・列を足すだけ・NOT NULL は付けない）
```sql
-- セット：RPE・休憩秒・補助
ALTER TABLE karte_tr_sets ADD COLUMN rpe REAL CHECK (rpe IS NULL OR (rpe >= 0 AND rpe <= 10));
ALTER TABLE karte_tr_sets ADD COLUMN rest_s INTEGER CHECK (rest_s IS NULL OR (rest_s >= 0 AND rest_s <= 900));
ALTER TABLE karte_tr_sets ADD COLUMN assisted INTEGER CHECK (assisted IS NULL OR assisted IN (0, 1));
-- 種目のメモ（種目ごとに1つ）：セットの表に置くと「どのセットの行に持つか」が曖昧になるので、小さな子の表にする
CREATE TABLE IF NOT EXISTS karte_tr_exercises (
  session_id TEXT NOT NULL REFERENCES karte_tr_sessions(session_id),
  exercise   TEXT NOT NULL,
  ord        INTEGER,            -- 並び順（B4 で使う）
  note       TEXT,               -- フォーム・器具（100字）
  PRIMARY KEY (session_id, exercise)
);
```
- **既存の karte_tr_sets.note は使わない**（画面に欄が無く、中身は空のはず＝未確認・本番で数える）。消さずに残す
- 0.5 刻みの RPE を許すか（REAL）は決めること（7）
- 列に新しい値を足すときは CHECK を grep する（feedback_new_enum_value_check_schema）。検査は本物の SQLite に migration を流して通す

### 4-3. B2（回／秒／分）の注意
reps の `NOT NULL CHECK (reps BETWEEN 1 AND 100)` と weight_kg の `NOT NULL` は、ALTER では外せない。外すには
「新しい表を作る→写す→名前を替える」作り直しが要る（D1 で可能だが、karte_tr_sets を参照するものの洗い出しと、写しの件数照合が要る）。**今回はやらない**。

### 4-4. 窓口
| 窓口 | 変更 | 許可表 |
|---|---|---|
| k_training | 応答に `karteSchema` を足す（**いまは返していない**）。A の後は rpe・rest_s・assisted・種目のメモも返す | 既存 |
| k_addTraining | A：セットに rpe・rest・assisted、種目に note を受ける。**総セット数の上限**を足す（4-5） | 既存 |
| **k_editTraining（新）** | A4：sessionId・rev・変更。set_id ごとに「鍵がある列だけ UPDATE」／新しいセットは INSERT／消すセットは set_id で DELETE。G.rowLive・G.author・G.rev（既存の deleteTraining と同じ守り）。karte_revisions に前の中身（数値と種目名だけ）を追記 | **perms.js の許可表に `'k_editTraining': ['trainer']` が要る**。名前は `isKarteWrite` の `/^k_(save|add|edit|delete|record)/` に当たる＝入口の書き込みの守り（Origin・トークン10分）が掛かることを検査で確かめる |

- 新しい窓口は KARTE_HANDLERS と perms.js の**2か所**に足す。揃っているかの検査を同時に書く（feedback_find_all_copies_of_a_list）

### 4-5. 本文16KB
いまの上限（20種目×10セット）に RPE・休憩・補助・種目のメモを足すと、最大の正規の要求が16KBを超えうる
（概算：セット1つ約55バイト×200＝約11KB＋種目名 50字×3バイト×20＝3KB＋メモ 100字×3バイト×20＝6KB）。
案：**1回の記録の総セット数を60まで**にする（実際は6〜8種目×3〜4セット）。最大の形の要求のバイト数が16KB以下であることを検査で固定する（設計31 確定事項7 と同じ）。

## 9. 関門①（Codex）を受けた確定事項（第1回の実装の仕様）
1. **送る中身は送信の直前に「✓のセットだけ」から作り直す**。前回の呼び出し・複製・下書きの復元のどの経路でも✓の初期値は false。下書きに✓も保存する。✓が0の種目は送らない・全体で0なら送らない。保存前の確認の件数は「値が入っていて✓の無いセット」だけ。赤枠は「値があるのに✓が0の種目」だけ
2. **下書きの状態は2つ**：編集中（draft）と、送ったが応答が分からない（pending＝送った中身と clientReqId を固定）。pending があるあいだは編集させず「同じ内容で送り直す／記録を確かめる／破棄して入れ直す」だけを出す。送り直しは固定した中身と同じ clientReqId だけ。はっきりした応答（成功・400・403・409 など）が来たら pending を解き、次の保存は新しい clientReqId。REQ_REUSED は「この送信番号は別の内容で使われています。記録を確かめてから、必要なら新しく保存してください」
3. **トークン切れの退避はトレーニングについては下書きに一本化**：sessionStorage には中身を入れず {kind:'training'} だけ。戻すときは localStorage の下書き（pending）を読む
4. **送る直前に** state.trainerId・cur.customerId・下書きの trainerId/customerId の一致を確かめ、違えば送らない（下書きも消さない）
5. 端末に残るもの：氏名は入れない。開くたびに期限切れ（24時間）の下書きを**実際に消す**。成功・破棄で消す。戻すときに「この端末に最大24時間残ります」と出す。共用の端末が無いことは運用で確かめる（未確認として残す）
6. **「前回」＝入力中の日付より前の、session_id 単位の直近の1回**（同じ日の2回をまとめない）。日付を変えたら作り直す。ボタンに「前回 11/1・担当 ○○」。直近20回の中だけで探し、before のページングは使わない（Worker の並びと before の条件が合わないため）
7. 休憩タイマーは1つだけ・終了予定の時刻から残りを計算（裏に回っても狂わない）・次の✓でやり直し・✓を外しても止めない（止めるボタンあり）・画面を移ると消える・振動は使えれば。「記録には保存されません」と出す
8. 経過日数は日本の暦日の差（YYYY-MM-DD どうし）。同じ日は「今日実施済み」。「種目名から自動判定」と出す
9. 総セット数60：画面は60で追加を止めて残りを出す。Worker は正規化の後に数えて **TOTAL_SETS**（400）。画面はこれを「合計60セットまで」と出す
10. k_training は記録が0件でも karteSchema を返す。画面は履歴を読み終えてからフォームを作る。応答は「頼んだ顧客＝いまの顧客」のときだけ使う
11. 保存の後の「指導メモを書く」は、保存した日付で開く（今日ではない）
