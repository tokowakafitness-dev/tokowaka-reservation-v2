## 4. 保存の置き場所・鍵・時機（C）

### 4-1 鍵と形
```
鍵   'karte_ai_review_v1:' + trainerId + ':' + customerId      （記録の下書き TR_DRAFT_PREFIX と同じ並び）
値   { v: 1, tid, cid, day: 'YYYY-MM-DD'（日本の日付）, at: 保存した時刻, scope: 'full'|'trial',
       hash: 文字起こしのしるし（§6・作れなければ ''）, dropped: 体のことの言葉で保存しなかった行の数,
       rv: { v: 3, effort, exercises: [...], fields: {...}, member: {...} } }   ← 中身は §5 の表だけ
```
- 読み書きは既存の `lsGet`・`lsSet`・`lsDel`（1244〜1246行。例外は握って null／false）。
- 読むときは `tid`・`cid` が今と一致・`v === 1`・`rv.v === 3`・`scope` が今の `aiScope()` と一致・`day` が今日・`at` が24時間以内・形の検査（§7）が通る、の全部を満たすときだけ使う。

### 4-2 保存する時機
- **編集のたび**：rvFoot（3028行・1行・欄・名前・メモを打つたびに呼ばれる）と、外す／戻す／部位／チェック／種目を足すの後の draw（drawReview の最後で rvFoot を呼ぶ）で保存する。1回の書き込みは数KB（60セット・欄の文章）＝打つたびでも端末の負担は小さい。
- **振り分けの応答を受け取った直後**（2592行の reviewFromDraft の後）に1回保存する（何も直さずに離れても残る）。
- 「離れるとき」だけに頼らない（LINE の中の画面は pagehide が来ないまま落とされることがある＝未確認。編集のたびに保存すれば要らない）。

### 4-3 消す時機
| とき | 消すか |
|---|---|
| 「記録の画面に入れる」が成功した（commit の `lsSet(key, T)` が成功した直後・2749行の後） | 消す（入れた後に続きから出すと二重に入る） |
| 新しい振り分けの応答を受け取った | 上書き（1つのお客様に1つ） |
| 「捨てて最初から」を押した | 消す（§8 の取り消しの間はメモリに持つ） |
| 期限切れ（日付が変わった・24時間を超えた） | 開くたびに消す（purgeTrDrafts に同じ接頭辞を足す） |
| 形の検査に落ちた・版が違う・scope が違う | 消す（§7） |
| 貼り付け欄を変えた（ta.oninput で rv を捨てる） | **消さない**（誤って欄を触っても続きが残る。帯が再び出る） |
| 確認画面で「読み取る」を押した | 消さない（同上） |

### 4-4 期限：当日中（日本の日付が同じ）かつ24時間以内
- 記録の下書きは24時間（1234行）。振り分けはその日のセッションのためのもので、日付をまたいで続きから入れると commit が新しい下書きの日付を今日にする（2717行 `sessionDate: today()`）＝**前日のセッションの数字を今日の記録として入れる**おそれがある。だから日付が変わったら使わない。

## 5. 何を保存するか（★I63 を変える部分）

| rv の部分 | 保存 | 理由 |
|---|---|---|
| 種目名・元の種目名（name0）・外した・部位（part／partFor） | する | 再開に要る。記録の下書きにも種目名は入る |
| セットの1行（line） | する | 同上 |
| 元のセットの状態と数字（orig の status・w・r・bw） | する | 色（出所）と記録の画面の印（src）を再開後も同じに出すため（設計50 §5-3-3）。数字は記録の下書きにも入る |
| 元のセットの根拠（evidence）・迷った理由（unsure） | **しない** | 文字起こしの切り出し＝原文の一部（雑談・伏せ切れない名前を含み得る）。記録の下書きには入らない種類の情報。再開後は「根拠を見る」に「保存していません」と出す |
| 聞こえた言葉（heard） | **しない** | 同上（文字起こしの切り出し） |
| 種目のメモ・欄の文章（今日の流れ・状態・指導・ヒアリング・次回やること） | する（**体のことの言葉の行は除く**） | 入れれば社内メモとして記録の下書きに入る種類の情報（§1-6）。体のことの言葉の行はもともと入れられない（設計50 で押せない）＝保存しない。除いた行数を `dropped` に数え、再開の帯に「体のことの言葉を含む N 行は保存していません」と出す（黙って落とさない） |
| お客様に見える欄（お客様へ・次回までに・チェック） | する（体のことの言葉の行は除く） | チェックの状態も含めて再開に要る。チェックは既定オフのまま保存されていたものだけを戻す |
| 体のこと（caution） | **しない** | 健康情報は端末に退避しない（965行の方針・I55）。再開後は「体のこと：保存していません（必要なら振り分け直す）」と1行 |
| AI が分からなかった点（unclear） | **しない** | 文字起こしの切り出し・何でも入り得る。読むだけの情報で入れる操作が無い |
| 文字起こしの原文 | **しない** | I63 のとおり。しるし（§6）だけ |

- 比べた案：**全部保存する**（再開後も根拠・体のこと・分からなかった点まで出る）。✗ 健康情報と原文の切り出しが端末に最大1日残る（965行の方針と I63 の両方に反する）。共有の端末で別の人が保存領域を読めば見える。
- 推奨は上の表（**記録の下書きに入る種類の情報だけを保存する**）。端末に新しく残る情報の種類は増えない（記録の下書きと同じ種類・同じ期限以内）。増えるのは「入れる前の、トレーナーが直している途中の文」と「AI の判定（状態と数字）」だけ。

## 6. 同じ文字起こしは送り直さない（しるしで照合）

```
しるし = SHA-256( 'karte-ai-v1:' + trainerId + ':' + customerId + ':' + 欄の文字を trim したもの ) の16進
         （crypto.subtle.digest。使えない端末では '' ＝照合しない＝今どおり送る）
```
- 「AIで振り分ける」を押したとき、保存があり・§4-1 の条件を満たし・`hash` が空でなく今の欄のしるしと一致すれば、**送らずに保存から確認画面を出す**。1行の知らせ「同じ文字起こしの振り分けを、続きから出しました（回数は使っていません）」と、［振り分け直す（1日の回数を1回使います）］（44px）を出す。振り分け直すを押したときだけ今どおり送る。
- 原文は保存しない。しるしはトレーナー・お客様ごとに異なる前置きを付ける（別のお客様の同じ文と一致しない）。文字起こしは長く、しるしから元の文を戻すことはできない。
- 照合は「文字が完全に同じ」ときだけ（trim の後）。1字でも違えば送る（今と同じ）。
- 送る前に照合するので、しるしの計算（数ミリ秒・非同期）の間は「AIで振り分ける」を押せない状態にする（二度押しを防ぐ・今の aiBusy と同じ扱い）。

## 8. 再開の見せ方

```
取り込み画面の一番上（貼り付け欄の上）に1つの帯：
┌ 前回の振り分けが途中です（14:05・種目4・セット7）              ┐
│ ［続ける］                     ［捨てて最初から］                │  ← どちらも44px以上・横に並べる（誤タップしにくい間隔）
│ 根拠・体のこと・分からなかった点は保存していません               │
│ （体のことの言葉を含む N 行は保存していません）                  │  ← dropped>0 のときだけ
└────────────────────────────────────┘
```
- ［続ける］：保存から rv を作って確認画面を出す（API を呼ばない）。
- ［捨てて最初から］：保存を消し、帯を「捨てました［元に戻す］」に変える（確認のダイアログは出さない）。元に戻すは、この画面を離れるか、AI で振り分けるか、貼り付け欄に何か入れるまで押せる（捨てた中身はメモリにだけ持つ）。
- 記録の画面の「メモから取り込む」（3214行）は、保存があるとき「メモから取り込む（振り分けの途中あり）」と出す（誤タップで記録の画面に戻ったときに気づける）。
- 時刻は保存の `at` から日本の時刻の時:分。件数は保存の rv から設計50 の reviewTally で数える。
- 帯の文字に氏名・文章の中身は出さない（件数と時刻だけ）。

## 9. 同じ端末を複数のトレーナーが使う・ログアウト

- 鍵に trainerId を含み、読むときに `tid` の一致を確かめる＝別のトレーナーの画面には出ない（記録の下書きと同じ・2426行）。
- ただし保存そのものは端末に残る（最大で当日中）。記録の下書きと同じく、ログアウトで消す処理は置かない（いまログアウトの経路は外部ブラウザの読み直しだけ＝386行。LINE の中ではログアウトしない）。共有の端末での残り方は記録の下書きと同じ水準で、**中身は記録の下書きと同じ種類の情報だけ**（§5）。
- 比べた案：開くたびに「自分以外のトレーナーの保存」を消す。✗ 同じ端末を交代で使う途中で、前の人の続きが消える。記録の下書きもそうしていない。採らない。

## 12. CEO に判断してほしい点

1. **I63 を改めて、確認画面の途中の状態を端末に当日中だけ保存してよいか**（手段 C）。保存するのは記録の下書きに入る種類の情報だけ（種目・1行・元の状態と数字・欄の文章・お客様の欄）。根拠・迷い・聞こえた言葉・体のこと・分からなかった点・体のことの言葉の行・原文は保存しない。推奨：**保存する（C）**。保存しない場合の次善は B（カルテの中の変数に持ち、同じ文書の中の移動だけ守る・I63 は変わらない・読み直しやアプリから出ると消える）。
2. **同じ文字起こしは送り直さない（しるしの照合）を入れるか**。推奨：**入れる**（オーナーの「課金が困る」に直接効く・原文は保存しない・別のお客様と一致しない前置き）。
3. **期限は当日中かつ24時間以内でよいか**。推奨：当日中（日付をまたいで続けると、前日の数字を今日の記録として入れるおそれ）。
4. 再開後は「根拠を見る」「体のこと」「分からなかった点」が出ない（保存しないため）。必要なら振り分け直す（1回分使う）。これを受け入れるか。推奨：受け入れる（健康情報と原文の切り出しを端末に残さない方を取る）。
