# TOKOWAKA 予約・契約 API（Cloudflare Workers）

LIFFの表示を速くするための読み取りAPI。いまGASが13回・58秒かけている範囲を、4回・数秒にする。

## なぜ作るか（実測・2026-09-28）

`liff.init` は **18ms**。遅さは100%がGAS側だった。
言語を1つ保存するだけの `setLang` が **3,840ms** かかっている＝**何もしない処理でも約2.5秒**。
745KB・11,000行を毎リクエストで読み直す起動コストで、**全体58秒のうち約32秒（55%）**を占める。

| | 現在 | 第1段階 | 第2段階 | 第3段階 |
|---|---|---|---|---|
| 通信回数 | 13回 | 8回 | 4回 | 4回 |
| 合計 | 58.1秒 | 約15秒 | 約2.5秒 | **約0.5秒** |
| 範囲 | — | 読み取りをWorkersへ | 書き込みもWorkersへ | カレンダー反映を非同期に |

## 設計

### 入口は1本（`src/index.js`）
すべてのリクエストが同じ順序を通る。個々の処理に権限チェックを書かない。

```
① ID Tokenの署名検証（src/auth.js・WebCryptoで自前検証＝外部通信ゼロ）
② 役割の確定（guest / customer / trainer / owner）
③ 許可表の照合（src/perms.js）← 表に無い組み合わせはここで終わる
④ 処理
⑤ 役割に応じて応答から機密を落とす（redact）
```

**契約の金額を扱う操作は顧客の表に載せない。** 載っていない＝通らない。
**粗利はオーナーの表にだけ載せる。** トレーナーにも出さない（2026-09-27 オーナー指示）。
③で表を通った後も⑤で落とすので、二重になっている。

検証：`node worker/test/perms.test.js`（38件）

### データの置き場所
| データ | どこ | 理由 |
|---|---|---|
| トレーナー名簿・空き枠・残数の写し | **KV** | みんなが同じものを読む。エッジで20〜40ms |
| 契約・顧客・予約・カルテ | **D1** | 一人ひとり違う。正確さが要る |

**表示はKV、確定はD1。** KVは書いてから各拠点に行き渡るまで数秒かかるため、
二重予約の判定には使わない。現在のGAS（キャッシュ表示＋カレンダーのリアルタイム照合）と
同じ分担で、照合先が速くなるだけ。

### 第1段階での真実の所在
D1は**写し**。真実はスプレッドシート（契約）とGoogleカレンダー（予約）のまま。
GASが押し出し、Workerは読むだけ。`/health` で同期の鮮度を確認できる。

## 立ち上げ手順

### オーナーの操作（3つ）

**1. Cloudflare APIトークンを作る**

ダッシュボード → マイプロフィール → APIトークン → **カスタムトークンを作成**。
権限は3つだけ。アカウントリソースは当該アカウントのみに限定する。
**グローバルAPIキーは使わない**（全権限を持つため）。

| 種別 | 対象 | 権限 |
|---|---|---|
| アカウント | Workers スクリプト | 編集 |
| アカウント | D1 | 編集 |
| アカウント | Workers KV ストレージ | 編集 |

**2. GitHub Secrets に登録する**（値は画面にも履歴にも残らない）

```
gh secret set CLOUDFLARE_API_TOKEN --repo tokowakafitness-dev/tokowaka-reservation-v2
```

**3. セットアップを1回だけ動かす**

GitHubの **Actions** タブ → 「Worker セットアップ（初回1回だけ）」 → **Run workflow**。
D1とKVが作られ、ログにIDが出る。そのIDを伝えてもらえれば `wrangler.toml` に反映する。

### 以降
`worker/` を変更して push すれば、`worker-deploy` が自動でスキーマ適用とデプロイを行う。
オーナーの操作は不要。

## ファイル

```
worker/
  wrangler.toml          設定（D1/KVのIDはセットアップ後に埋める）
  schema.sql             D1のスキーマ。何度流しても同じ結果になる
  src/
    index.js             入口1本。①〜⑤の順序を強制する
    auth.js              LINEのID Tokenを自前で署名検証（JWKSはKVに12時間寝かせる）
    perms.js             許可表と除去ルール。ここだけが権限を決める
    routes/
      boot.js            起動時の一括取得（現在5回・21秒 → 1回）
      customer.js        顧客詳細の一括取得（現在4回・16.7秒 → 1回）＋契約履歴
      slots.js           空き枠（KVから配る）＋予約オプションを同梱
  test/perms.test.js     許可表の回帰テスト
```
